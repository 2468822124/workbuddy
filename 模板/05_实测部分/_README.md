# 实测部分模板

本分类服务新规则下的功能用户实测阶段。它与旧的 `04_反馈部分` 并存：旧模板和历史文件保留用于审计，新轮次优先使用本分类。

首份当前目标版本计划绑定 `C0/S0`；Fix/Review 后的后续计划绑定新的 `QA/S` 不可变快照。只有首份 `C0` 计划要求核对开发完成、Git 提交和干净工作树，后续计划以 `S` 快照的来源指纹、独立构建目录和构建物哈希为门，不要求重新提交 Git。

## 模板列表

- `项目测试计划模板.md`：GPT 在开发结束硬前置通过后创建的 `R<N>-<n>` 测试计划，或在所有活跃 R 关闭后创建的 `G1` 版本级整合计划。GPT 与用户共用同一份计划，各自执行明确范围。
- `用户实测问题全流程闭环模板.md`：`13` 创建或续写的同一问题来源轮次唯一闭环文档，合并 GPT 报告、用户回传、Fix、Review、轮次分流和 G1。
- `模板/GPT实测记录模板.md`：GPT 独立客观实测报告的唯一模板，仍放在模板根目录，报告写入 `GPT实测记录/`。

## 轮次与批次

- `R1/R2`：问题来源轮次；只因新独立问题开启新轮次。
- `R1-1/R1-2`：同一轮内的实际测试计划，每次重新测试都新建计划。
- `Fix1/Fix2`：DeepSeek 修复批次，回写同轮唯一闭环文档。
- `Review1/Review2`：GPT 复审批次，回写同轮唯一闭环文档。
- `G1`：所有活跃轮次关闭后的版本级整合回归，不开启新问题轮次。

## 落点

```text
用户实测阶段\vX-功能名\第N轮\vX第N轮用户实测计划（n）.md
用户实测阶段\vX-功能名\第N轮\vX-第N轮-问题概述-全流程闭环记录.md
用户实测阶段\vX-功能名\第N轮\R1-1相关证据\
GPT实测记录\vX实测内容\第N轮\vX-R1-1-GPT实测.md
GPT实测记录\vX实测内容\第N轮\证据\R1-1-<测试点>-<场景>.png
用户实测阶段\vX-版本级整合\G1\vX-G1版本级整合测试计划.md
用户实测阶段\vX-版本级整合\G1\用户证据\G1-T<NN>-<场景>.<扩展名>
GPT实测记录\vX实测内容\G1\vX-G1-GPT实测.md
GPT实测记录\vX实测内容\G1\证据\G1-T<NN>-<场景>.png
```

同一 `R<N>` 只能有一份全流程闭环文档；测试计划和 GPT 报告可以有多份。G1 不属于 R，也不创建问题闭环文档，只回写 G1 计划的合并区。缺少 GPT 或用户正式证据时，13 只能停止或建立 `📝待补证据` 草稿，不能进入 Fix。

用户 06 不需要重复填写快照信息；GPT 从测试计划核对双方使用同一个 `S` 构建物。所有活跃 `R` 轮次关闭后执行 `G1`，`G1` 通过且用户完成最终验收后才形成 `C1`。

## 维护方

- **GPT**：测试计划、GPT 客观报告、问题分类/诊断/编排、复审和闭环裁决记录。
- **用户**：亲自执行计划中的用户范围和共同核心链路，通过 06 回传事实与主观体验。
- **DeepSeek**：按 07 执行代码修复、更新真实的 `当前代码状态.md`，并回写 Fix 修复说明。
