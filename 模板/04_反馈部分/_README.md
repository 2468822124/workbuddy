# 反馈部分模板

本分类保留历史用户反馈和维护期 CR 模板。新规则下的用户实测轮次优先使用 `模板/05_实测部分/`，避免把一次测试计划误建成一份新的问题文档。

新规则的版本/快照关系以 `规范类/项目代称.md` 为准：首份实测计划使用 `C0/S0`，后续 Fix/Review 使用 `QA/S`；本分类不另建快照或替代 05 实测模板。

## 模板列表

- `用户实测反馈部分编写模板.md`：历史反馈内容或兼容场景的反馈环节。
- `变更请求部分编写模板.md`：维护期 CR 的变更请求/规格环节。

## 新用户实测入口

- `用户prompt/06-用户反馈测试问题.md`：用户提交“发现问题 / 全部完成且无问题 / 无法完成-环境阻塞”三态回传。
- `用户prompt/13-生成用户实测全流程闭环.md`：R 模式创建/续写同一 `R<N>` 的唯一全流程闭环文档；G1 模式只回写 G1 计划合并区。
- `模板/05_实测部分/项目测试计划模板.md`：每次实际 R 测试新建一份 `R<N>-<n>` 计划；所有活跃 R 关闭后创建独立 `G1` 计划。
- `模板/05_实测部分/用户实测问题全流程闭环模板.md`：合并 R 模式双方实测、Fix、Review 和轮次分流；G1 使用项目测试计划中的合并区。

## 历史兼容规则

- 现有 v0.3 及更早文件原样保留，不迁移、不重写。
- 新轮次不按每个问题创建多个全流程文档；同一 `R<N>` 只有一份。
- 缺少 GPT 或用户正式证据时，只能标记 `📝待补证据`，不得进入修复闭环。

## 维护方

- **GPT**：计划、证据门禁、诊断、问题分类、复审和文档编排。
- **用户**：实际执行并通过 06 提交事实与体验。
- **DeepSeek**：按 07 执行代码修复并回写 Fix 说明。
