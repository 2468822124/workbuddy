# WorkBuddy v0.3 用户测试流程

> **测试对象**：任务数据流通重构（v0.3）
> **测试版本标记**：`v0.3`
> **测试环境**：`E:\workbuddy-test` 隔离测试专用
> **测试目的**：由最终用户在 Windows 桌面环境中验证 v0.3 的完整任务数据流、页面交互、数据安全和错误降级。
> **测试性质**：用户实测流程，不替代阶段 1-6 的 GPT 开发审查结论；本流程的最终结果决定 v0.3 是否达到用户实测闭环。

---

## 1. 版本边界

### 1.1 本次必测范围

- 周统筹：月目标、周核心推进目标、临时任务、场次型任务、固定任务和本周可安排任务。
- 日规划：当日任务、rail 选取、自由任务、顺延、跳过、锁定行、模板和日感想。
- 今日总览：任务汇聚、项目任务投影、提醒投影、手动待办、完成状态和昨日复盘摘要。
- 复盘与趋势：周完成率、顺延/未完成/未安排/跳过统计、趋势图、周/月感想和历史周转下周。
- 项目与设置兼容：项目任务新增/完成/删除、加入今日、数据导入导出、旧规划数据归档入口。
- 旧入口兼容、窗口自适应、首次启动、重复操作幂等和失败降级。

### 1.2 本次不验收范围

- LLM 自然语言手帐输入、AI 任务引导和 AI 复盘草稿生成；这些能力不属于 v0.3 的确定性任务流交付范围。
- 完整循环任务、知识库/Obsidian 数据迁移和新的项目/提醒模块重写。
- 修改已发布迁移脚本、手工编辑生产数据库或把测试数据上传到云端。

已有设置中的 AI 连接测试、热点刷新等能力可作为回归项记录，但不作为 v0.3 核心通过条件。

---

## 2. 测试环境与数据安全

### 2.1 启动与重置

1. 关闭当前 WorkBuddy 窗口。
2. 双击 `E:\workbuddy-test\启动实测.bat`。
3. 测试数据只写入 `E:\workbuddy-test\userData\`，数据库为 `E:\workbuddy-test\userData\workbuddy.db`。
4. 需要从干净状态重测时，先关闭 WorkBuddy，再双击 `E:\workbuddy-test\重置实测数据.bat`，确认后重新启动。

> 重置脚本会删除测试专用的 `userData`，不会删除或修改 `%APPDATA%\workbuddy\` 下的真实数据。不要直接删除、替换或编辑真实数据库。

### 2.2 测试数据命名

建议所有测试对象使用统一前缀 `[v0.3测试]`，例如：

- 月目标：`[v0.3测试] 本月主目标`
- 周任务：`[v0.3测试] 完成数据流测试`
- 项目：`[v0.3测试] 测试项目`
- 手动任务：`[v0.3测试] 手动待办`

这样可以在重复测试、导出和问题报告中快速区分测试数据。

### 2.3 测试记录原则

- 按本文顺序执行；除非某项失败需要停下记录，否则不要跳过前置数据流。
- 每个场景都填写“实际结果”和“结论”，不要只记录最后一项。
- 截图至少包含页面标题、测试对象和错误提示；不要截图暴露 API Key 或真实私人数据。
- 出现数据丢失、页面白屏、应用崩溃、错误数据写入或未授权网络发送时，立即停止后续相关步骤并报告。

## 3. 通过标准与六轮流程

| 轮次 | 验证主题 | 必测 |
|---|---|:---:|
| 0 | 启动、隔离、首次使用和窗口自适应 | 是 |
| 1 | 月目标 → 周统筹 → 固定/临时任务 | 是 |
| 2 | 周任务 → 日规划 rail → 今日任务 | 是 |
| 3 | 项目/提醒/手动待办汇聚到今日总览 | 是 |
| 4 | 完成凭据 → 复盘统计 → 趋势/封账/转下周 | 是 |
| 5 | 导入导出、旧入口、错误降级和数据安全 | 是 |

单项通过条件：操作后页面状态、计数、来源、日期和反馈均符合预期；数据在相关页面重新打开后仍一致。整体验收条件：必测项全部通过，无阻断级问题，且用户确认该版本可以按自己的工作方式使用。

## 4. 第 0 轮：启动与基础状态

### 0.1 干净启动

1. 重置测试数据并启动 `启动实测.bat`。
2. 等待窗口出现，不要在启动过程中重复双击脚本。

**预期**：

- WorkBuddy 窗口正常显示，不闪退、不白屏、不出现 `better-sqlite3`、`.node` 或数据库初始化错误。
- 默认进入“今日总览”；页面有空态卡，而不是空白页面。
- 首次启动提示条可见，提示前往“设置”完成配置；它是页面内提示，不应阻塞整个窗口。

### 0.2 首次配置与持久化

1. 进入“设置”，在“通用设置”填写称呼，修改晨间时段，离开输入框或触发保存。
2. 返回“今日总览”，确认问候语或相关称呼已更新。
3. 退出应用并重新启动。

**预期**：称呼和晨间时段保持；首次启动提示在确认后不再重复出现。若未配置 AI，AI 相关测试按钮应保持禁用，不影响确定性任务流。

### 0.3 窗口和响应式布局

1. 将窗口缩小到可用的较窄尺寸，再恢复到正常尺寸。
2. 依次打开“今日总览”“日规划”“周统筹”“复盘趋势”。

**预期**：内容能够换行或变为单列；没有关键按钮被遮挡、页面横向溢出、白屏或布局错位。恢复窗口后数据和当前页面不丢失。

## 5. 第 1 轮：月目标与周统筹

### 1.1 新建月目标

1. 从左侧“规划”展开入口，进入“月指导”。
2. 确认默认显示当前月份，点击右上角新增按钮。
3. 新建 `[v0.3测试] 本月主目标`，保存。
4. 修改标题并保存；再取消一次编辑。

**预期**：目标只出现在当前月份；新建、改名和取消都有明确结果。切换上月/下月再回来，目标仍在原月份；未关闭目标可在历史未关闭区域看到。

### 1.2 月目标关闭和删除

1. 为另一个临时目标点击“关闭”，先观察确认状态，再确认。
2. 为一个不再需要的临时目标点击“删除”，先取消一次，再重新确认删除。

**预期**：关闭目标显示已关闭且不再允许普通改名；删除需要行内二次确认，取消不会删除，确认后只删除目标本身，不影响已经写入的周感想或其他任务。

### 1.3 周统筹基础与周核心目标

1. 进入“周统筹”，确认默认是当前周。
2. 在“本周核心推进目标”中从月目标选取 `[v0.3测试] 本月主目标`，再手动新增一个核心目标。
3. 将其中一个标记完成，再取消完成；尝试删除一个临时目标并取消确认。

**预期**：月目标选取后标题正确显示；核心目标完成状态即时变化；删除有二次确认；月目标和周目标不会因为切换页面而互相覆盖。

### 1.4 临时任务和场次型任务

1. 在“本周任务清单”新增一次性任务 `[v0.3测试] 完成数据流测试`。
2. 再新增场次型任务 `[v0.3测试] 场次测试`，目标场次设为 3。
3. 一次性任务点击完成；场次型任务连续记录 1 场、再记录 2 场。

**预期**：一次性任务显示完成；场次型任务计数从 `0/3` 变为 `1/3`、再变为 `3/3`，完成态由凭据派生，不需要刷新页面。

### 1.5 每周固定任务与克隆

1. 在“每周固定”新建 `[v0.3测试] 固定任务`，选择一个惯常日；可同时测试一次型或场次型。
2. 修改惯常日并保存，观察页面提示。
3. 切换到下一周，再返回当前周；停用一个临时固定定义并取消一次确认。

**预期**：新周会按惯常日生成固定任务实例；固定定义的改名/惯常日只影响未来克隆，不改写已经生成的本周实例；停用需要确认，已存在的实例仍可查看。

### 1.6 本周可安排 rail

1. 找到“本周可选取”区域。
2. 确认尚未安排的周任务出现在 rail，点击一次“选取”。
3. 再次查看 rail 和本周任务清单。

**预期**：选取后该任务从 rail 消失，并在相应日计划/安排计数中出现；重复进入页面不会重复生成同一安排。

---

## 6. 第 2 轮：日规划、rail 与模板

### 2.1 当日任务和日期导航

1. 进入“日规划”，确认默认日期为今天。
2. 使用前一天、今天、后一天按钮切换日期；再用日期选择器跳到一个明确的日期。
3. 在昨天、今天和明天分别观察任务列表。

**预期**：日期与页面标题同步；不同日期的任务不串档；历史日期显示只读提示或限制，不允许把任务重新选入历史日；非法或不存在的日期应回落到合法默认日期，不得白屏。

### 2.2 自由任务新增、改名、完成与移除

1. 在日规划新增 `[v0.3测试] 日规划手动任务`。
2. 勾选完成，再取消勾选。
3. 使用改名按钮改为 `[v0.3测试] 日规划手动任务-已改名`。
4. 打开“挪到其它日”，选择明天并确认；回到今天查看该任务。
5. 对一个临时任务点击“跳过”，先取消确认，再确认跳过；对另一个临时任务点击移除，先取消，再确认移除。

**预期**：完成状态即时变化；改名只修改当前自由任务；挪动后任务出现在目标日期并带有正确的顺延信息；跳过任务灰显且不计入未完成；移除需要确认，凭据保留规则符合页面提示，取消不改变数据。

### 2.3 周任务选取与锁定行

1. 返回今天的日规划，找到来自周统筹的 rail 任务并点击“选取”。
2. 查看新增的任务行，尝试点击改名、挪动和跳过。
3. 在周统筹修改该周任务名称，再回日规划观察。

**预期**：周任务进入日规划后有锁定标识；锁定行不能在日规划直接改名、挪动或跳过，页面应给出到周统筹修改的提示；源任务改名后，日规划显示跟随源任务变化。项目/提醒投影只允许来源跳转、勾选、备注和移出今日，不应修改源任务。

### 2.4 私有备注

1. 对一条自由任务和一条周任务打开“私有备注”。
2. 填写备注并保存，再打开查看；随后清空并保存。

**预期**：备注只在对应任务行显示；清空后消失；备注不会改变周任务标题、项目源数据或其他日期的任务内容。

### 2.5 模板新建、套用、编辑与删除

1. 在日规划的“模板”区域新建一个日模板，至少添加两项。
2. 套用模板，先取消确认，再重新套用并只勾选其中一项。
3. 修改模板名称或任务项，保存；对临时模板删除，先取消再确认。

**预期**：套用前可选择部分任务；套用后生成对应日任务；模板编辑不会改写已经生成的任务；删除需要确认，取消不产生变化；成功和部分失败均有页面内反馈。

### 2.6 日感想

1. 在日规划底部写一段 `[v0.3测试] 今日感想`，保存。
2. 切换到明天再返回今天。

**预期**：出现“已保存”反馈；返回后内容仍在；明天的感想为空或是独立内容，不覆盖今天。

---

## 7. 第 3 轮：今日总览与四渠道汇聚

### 3.1 周任务流入今日总览

1. 进入“今日总览”。
2. 查看“今日任务/今日待办”区域，找到前面安排到今天的周任务和自由任务。
3. 在今日总览勾选一条完成，再取消勾选。

**预期**：日规划、今日总览显示同一实体的最新状态；完成计数即时变化；不需要手工重复创建任务。重复进入或刷新页面不会重复出现。

### 3.2 项目任务投影

1. 进入“项目”，新建 `[v0.3测试] 测试项目`，状态设为进行中。
2. 进入项目详情，新增 `[v0.3测试] 项目任务`，计划日期设为今天。
3. 回到今日总览，勾选该项目任务；再从今日总览点击“查看来源”。
4. 在项目详情取消完成，观察今日总览。

**预期**：项目任务按计划日期投影到今日总览；今日勾选能回写项目任务，项目页同步显示完成；来源入口能回到项目详情；从今日移出只移除今日投影，不删除项目源任务。

### 3.3 提醒投影与手动待办

1. 若测试数据中已有今日提醒，确认其出现在今日总览并能查看来源。
2. 在“今日待办”手动新增 `[v0.3测试] 手动总览任务`。
3. 勾选、取消勾选，再删除临时任务。

**预期**：提醒、项目任务和手动待办能在同一总览看到，但来源标识不同；手动任务不要求项目来源；删除有确认，不影响其他渠道。

### 3.4 今日总览空态与热点回归

1. 清空或重置测试数据后重新查看今日总览空态卡。
2. 若要回归热点，点击热点卡刷新；在网络不可用时再次观察。

**预期**：空态有清晰提示且不报错；热点刷新失败时保留已有内容或显示可重试的空态/错误反馈，不无限转圈、不阻塞任务数据流。热点回归失败只单独记录，不要与 v0.3 核心任务流混报。

---

## 8. 第 4 轮：复盘、趋势、封账与转下周

### 4.1 进入复盘趋势

1. 进入“复盘趋势”，默认查看当前周；使用前后周按钮查看历史周。
2. 查看周完成率、日计划明细、近 8 周趋势、顺延清单、周任务状态。

**预期**：页面正常加载；没有任务时显示空态而不是白屏；趋势柱图和当前周标签与所选周一致；统计只反映实际完成凭据，跳过项不计入未完成。

### 4.2 回看完成、顺延和跳过

1. 回到前面制造数据的周，确认至少有一项已完成、一项顺延、一项跳过或未安排。
2. 回到复盘查看对应统计，点击日计划明细或相关任务入口（若页面提供）。

**预期**：完成率、顺延天数、未完成、未安排、跳过数量彼此一致；修改历史日的完成勾选后，复盘统计实时重算；不会出现旧缓存计数。

### 4.3 周/月感想保存

1. 在复盘页面分别填写周感想和月感想，保存。
2. 切换到另一周再返回；再切换月份相关数据。

**预期**：周感想按周保存，月感想按月份保存；页面有“已保存”反馈；保存失败时保留编辑内容并显示错误，不弹系统模态框、不清空草稿。

### 4.4 历史周封账视图

1. 选择一个已经过去的周，确认页面显示历史周/只读展示标识。
2. 观察历史周的未完成任务和“转下周”入口；尝试点击当前周不应出现的操作。

**预期**：历史周统计稳定可查；当前周不显示“转下周”；历史周未完成任务可以显式转为下周一次性任务，不自动循环、不重复生成。

### 4.5 转下周与幂等

1. 在历史周对一项未完成任务点击“转下周”，先取消，再确认。
2. 打开下一周，检查转出的任务；再次回到历史周重复观察，不要重复确认。

**预期**：下一周出现一次性任务并带有来源关联；历史周仍保留审计记录；重复操作不会生成第二条相同的下周任务；固定任务在下周的正常克隆不应与一次性转出任务混淆。

---

## 9. 第 5 轮：设置、数据安全与兼容回归

### 5.1 导出数据

1. 进入“设置”→“数据管理”→“导出 JSON”。
2. 选择测试专用目录之外的临时位置保存，例如桌面上的 `v0.3-test-backup.json`。
3. 用文本编辑器查看文件结构，不要把文件上传到网络。

**预期**：导出成功并有结果反馈；JSON 包含业务表数据，能看到测试项目和任务；API Key 不以明文出现在导出文件或应用日志中；日志不打印用户完整文件路径。

### 5.2 导入 round-trip 与取消

1. 先保留当前测试数据和刚才的备份文件。
2. 在设置点击“导入 JSON”，先点击取消。
3. 再次导入刚才的备份，确认覆盖提示后继续。

**预期**：取消不改变当前数据；确认导入后项目、任务、周任务和相关数据恢复；导入反馈显示成功或明确错误，不出现系统模态错误框；导入不能接受缺少必要表的空对象并清空原业务数据。

### 5.3 旧规划入口收口

1. 日常使用只从侧栏“规划”下的“日规划/周统筹/月指导/复盘趋势”进入。
2. 确认侧栏不再指向旧 Markdown 规划页面；四个正式页面均能从侧栏到达。
3. 如果使用开发者工具或专项脚本验证旧 hash 路由，检查 `/planning/daily`、`/planning/weekly`、`/planning/monthly`、`/plan`、`/review` 是否只重定向到对应新页面。

**预期**：用户日常不会进入旧模块；旧入口即使被历史链接访问，也不应白屏、加载旧页面或传递旧 Markdown 参数；月度旧日期参数应转换为合法月份。

### 5.4 未配置/错误配置 AI 的降级

1. 在设置清空 API Key 或 Base URL 并保存；观察设置中的测试连接按钮。
2. 填入错误 Key 或不可达 URL，点击“测试连接”。
3. 恢复正确配置或清空配置，继续打开其他任务页面。

**预期**：未配置时 AI 连接按钮禁用或给出前往设置提示；错误配置在限定时间内返回可读失败反馈；不崩溃、不无限重试、不弹系统模态框；任务、项目、复盘等非 AI 功能继续可用。不要将真实 API Key 写入问题报告。

### 5.5 隔离数据库损坏/只读（可选但建议）

> 只操作测试专用 `E:\workbuddy-test\userData`。开始前先关闭应用并复制一份整个 `userData` 作为恢复备份。

1. 关闭 WorkBuddy，把测试数据库复制为 `workbuddy.db.bak`。
2. 将 `workbuddy.db` 临时改名保存，再用同名文件写入不可读内容，启动测试应用。
3. 打开今日总览、周统筹、设置和复盘，尝试一次读操作和一次写操作。
4. 关闭应用，恢复备份数据库；或直接运行“重置实测数据.bat”重新开始。

**预期**：应用仍能创建窗口，不出现未处理异常；不可读数据库进入安全降级，读写通道返回统一的数据库不可用反馈；不应因为某一个通道未注册而崩溃，也不应写入伪造的缓存计数。若测试数据库无法恢复，删除测试 `userData` 并重置即可，真实数据库不受影响。

## 10. 关键禁止边界

以下任一现象应立即报告为阻断问题：

- 任务只写入 Markdown/自由文本，或页面与结构化任务数据不同步。
- 完成、跳过、顺延或统计结果依靠缓存字段，刷新/重新进入页面后数值不一致。
- 修改任务名称时通过文本匹配关联了另一条任务，或来源不是稳定 ID。
- 旧冻结区重新出现在 v0.3 正式入口，或旧页面被侧栏重新启用。
- 导入空对象/缺键载荷导致原有业务数据被清空。
- 损坏数据库导致应用崩溃、未注册 IPC、任意通道写入或静默伪造空数据。
- 导出文件、日志、错误消息或截图中出现 API Key 明文或不应外发的私人内容。
- 失败操作弹出系统模态框、无限重试、卡死，或没有页面内可读反馈。

## 11. 问题报告格式

每个问题单独报告，按下面格式填写：

```text
【测试版本】v0.3
【测试步骤】例如 2.3 周任务选取与锁定行
【我的操作】逐步描述点击、输入、日期和是否重置过数据
【预期结果】应该看到什么
【实际结果】实际看到什么，是否可重复
【影响范围】数据丢失 / 白屏崩溃 / 功能不可用 / 体验问题
【错误信息】页面反馈或日志文字；不要粘贴 API Key
【截图/录屏】附页面标题、测试对象和错误位置
```

严重度建议：

- `阻断`：崩溃、白屏、数据丢失、任务来源错乱、敏感信息泄露、错误边界未降级。
- `需修复`：核心流程无法完成、计数/日期/状态不一致、导入导出失败。
- `一般`：文案、布局、按钮反馈或不影响数据正确性的交互问题。
