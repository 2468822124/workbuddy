### 5. 技术设计（核心设计）

#### 5.1 今日总览壳层
- `/today` 继续是首页入口，不改侧边栏
- 页面保留原有新闻/热点/灵感卡片，任务区改为统一的 `DayEntryList`
- 今日页顶部保留一个明确的“去日规划”按钮，跳 `/flow/day?date=today`
- 今日页的任务区标题改为“今日总览”，空态文案改为“手动添加 / 从项目加入 / 提醒打卡”
- 今日页只负责展示和分发动作，不再自己维护 `todayTodos / overdueTodos` 两套旧列表

#### 5.2 同一实体双视图
- 今日页和 `/flow/day` 都读同一套 `flow_day_entries`
- 今日页是“今天视角”，日规划页是“任意日期视角”
- manual / rail / habit / template / deferred 仍按阶段3 规则表现
- project / reminder 是阶段4 新增的**来源投影行**：
  - `project`：来源是项目页里的某条 todo
  - `reminder`：来源是周/月打卡提醒
- 这两类行不是新的业务实体，只是同一日实体的来源投影

#### 5.3 来源感知动作矩阵
| source | 今日页表现 | 可改名 | 可挪动 | 可跳过 | 可移出今日 | 来源跳转 |
|---|---|---|---|---|---|---|
| manual | 自由任务 | 是 | 是 | 是 | 是 | 否 |
| rail / habit / template / deferred | 阶段3 逻辑 | 阶段3 规则 | 阶段3 规则 | 阶段3 规则 | 是 | 视情况 |
| project | 项目投影 | 否 | 否 | 否 | 是 | `/projects/:id` |
| reminder | 打卡投影 | 否 | 否 | 否 | 是 | `/flow/week` 或 `/flow/month` |

说明：
- `locked=true` 只表示标题不能在今日页直接改字
- `project / reminder` 的完成态以来源状态为准，不走阶段3 那套纯凭据派生
- `移出今日` 只删今日投影，不删源项目、不删提醒规则

#### 5.4 项目投影链路
- 项目页的某条 todo 通过“加入今日”按钮生成今日投影
- 投影行的 `projectId` 存的是**源 todo id**（字符串 UUID），不是旧 project 表 id
- 今日页 / 日规划页展示时，标题跟随源 todo 的当前标题
- 项目页改名后，今日投影自动跟随
- 今日页勾选后，必须回写到源 todo 的 `done/undone`
- 源 todo 被移出今日或删掉时，今日投影不得炸页，最多降级为软失败

#### 5.5 提醒投影链路
- 仍保留旧的提醒生成规则（周日 / 月末）
- 但今日页展示的是 flow 投影行，不再直接读旧 todos 列表
- 投影行使用稳定键 `reminderKey`：
  - `weekly`
  - `monthly`
- 提醒行的标题按当天提醒文案快照保存，来源跳转按键映射到 `/flow/week` / `/flow/month`
- 今日页勾选后，必须回写到对应的旧提醒 todo，保证旧页和新页同步
- 同一天如果提醒被移出今日，不得被同日的重复种入再次拉回来

#### 5.6 读写分工
- `flowDerived` 负责读时合成：标题、来源跳转、完成态、顺延分组
- `flowActions` 负责写时编排：新增投影、勾选回写、移出今日、去重
- `reminders.ts` 负责启动时种入今日提醒投影
- `useToday.ts` 只做今日页聚合，不直接碰 DB

### 6. 数据模型变更

#### 6.1 `flow_day_entries`
**DDL**：
```sql
-- 0009_today_channel_sync.ts
CREATE UNIQUE INDEX IF NOT EXISTS idx_fde_project_today_unique
ON flow_day_entries(date, projectId)
WHERE isDeleted = 0 AND source = 'project' AND projectId IS NOT NULL;

CREATE UNIQUE INDEX IF NOT EXISTS idx_fde_reminder_today_unique
ON flow_day_entries(date, reminderKey)
WHERE isDeleted = 0 AND source = 'reminder' AND reminderKey IS NOT NULL;
```

**TS 接口**：
```ts
export interface FlowDayEntry {
  // ...
  projectId: string | null
  reminderKey: string | null
}

export interface DayBoardEntry extends FlowDayEntry {
  done: boolean
  deferredCount: number
  displayTitle: string
  sourceHref: string | null
}
```

**向后兼容**：
- 不重建整表；SQLite 动态类型允许旧 `INTEGER` 口径继续承载字符串 UUID
- `projectId` 在本阶段逻辑上改成“源 todo id”
- `reminderKey` 仅在本阶段使用 `weekly / monthly` 稳定键

**索引与约束**：
- 今日项目投影同一日同一 source todo 只能有一个 active 行
- 今日提醒投影同一日同一 reminderKey 只能有一个 active 行
- 删除态 tombstone 不参与 active 唯一约束

#### 6.2 今日来源投影读模型
**新增派生字段**：
- `sourceHref`：今日行的来源跳转地址
- `displayTitle`：project 行跟随源 todo 标题；reminder 行跟随提醒快照

**读时规则**：
- `project` 行：从源 todo 批量取当前标题/状态/所属 projectId
- `reminder` 行：按 `reminderKey` 和今天日期取提醒标题与完成状态
- 其它 source：沿用阶段3 的 flow 规则

### 7. IPC 契约
**无新增通道**。只改既有通道语义与参数类型。

| 通道 | 变更 |
|---|---|
| `flow:entry:add` | `projectId` 从 `number` 改为 `string`；`project`/`reminder` 需要来源键，不再走旧数字外键 |
| `flow:entry:toggleCheck` | `project / reminder` 行改为源状态回写，不再只靠 flow voucher |
| `flow:entry:remove` | `project / reminder` 只移除今日投影，不删除源 todo / 提醒规则 |
| `flow:dayBoard` | 返回 `DayBoardEntry.sourceHref`，供今日页/日规划页做来源跳转 |

`preload/index.ts` 只需要同步更新 `flow.entry.add()` 的类型签名，不新增新 API 名称。
