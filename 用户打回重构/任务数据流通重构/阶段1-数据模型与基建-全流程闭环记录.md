### 5. 核心设计

#### 5.1 数据分层原则（本阶段一切实现的总纲）
- **写路径**：仓储只做行↔对象映射；业务动作（克隆/安排/跳过/凭据）在 service 组合仓储调用。
- **读路径**：`flowDerived` 是唯一"视图真相"出口——周完成态、rail、顺延、统计全部实时计算，**本阶段代码中不得出现任何"完成/消耗"落库字段**（技术栈规范 §4.5）。
- **关联**：实体间只准 id 引用（`weekInstanceId`/`fixedDefId`/`projectId`/`monthGoalId`），**禁止按标题文本关联**（§4 铁律，3.2 覆辙）。

#### 5.2 克隆引擎（flowCloneEngine.materializeWeek）
**设计逻辑**：无定时任务（立项 #10）；访问某周任何数据前先调 `materializeWeek(weekStart)`，幂等。
**实现细节**（伪代码）：
```
materializeWeek(weekStart):
  defs = flowFixedRepo.listActive()
  for def in defs:
    if not flowWeekRepo.exists(weekStart, def.id):        # 幂等判重
      inst = flowWeekRepo.create({weekStart, origin:'fixed', fixedDefId:def.id,
                                  title:def.title, kind:def.kind,
                                  targetCount:def.targetCount})
      for wd in bitmaskDays(def.weekdayMask):              # 惯常日自动安排
        flowDayRepo.create({date: weekStart+wd偏移, source:'habit',
                            locked:1, weekInstanceId:inst.id, title:def.title})
  return Result 包装修改计数
```
**边界**：同周重复调用零新增；`weekStart` 必须为周一（`shared/period.ts` 既有 `getWeekStart` 归一化，勿自写日期数学）；固定 def 软删后不再克隆（存量实例保留）。

#### 5.3 派生查询（flowDerived）
**完成态规则**（唯一事实=凭据池）：
| 实体 | done 判定 | 场次计数 |
|---|---|---|
| day_entry | 存在未删 `check` 凭据挂本行 | — |
| 周实例(一次性) | 挂实例的 manual 凭据 ≥1，或其任一未删安排行 done | — |
| 周实例(多次性) | doneCount ≥ targetCount | doneCount = 挂实例 manual/extra 凭据数 + done 安排行数（超额照计，展示 n/目标） |

**rail 可见性**（周面板）：`isDeleted=0 && skippedAt IS NULL && !done && (一次性: 无未删安排行 / 多次性: 安排行数 < targetCount)`——超额选取允许（目标内排满后 rail 隐藏，G4）。

**顺延（读时派生，零写入）**：日面板(date) = 当日行 ∪ {日期<date 且 未删 未跳过 未完成 且 source≠'reminder' 的行}，后者标 `deferredCount = (date − 行日期)天`。**不修改行数据**——与"实时派生·历史可改"铁律同构（立项 #5/#21）。

**改名传播**：🔒行与周完成态展示时经 `weekInstanceId` 取实例实时标题；固定 def 改名时同步 UPDATE 本周未删实例标题（源头显式传播动作，未来克隆自然继承）。

#### 5.4 出处直存（day_entry.source）
七值：`manual/rail/template/deferred/habit/project/reminder`，创建时写入，对应 sourceRef 字段见 §6。**禁止事后推断**（labelTodoSource 模式禁止复活）。`template` 出处仅作展示快照（复制断链，不联动）。

### 决策偏差（记录）

1. **新增 `flowActions.ts`（规格 §4 未列）**：规格只列 clone/derived 两服务，但周任务删除=软删实例+级联软删安排行、勾选=凭据池增删、锁定行禁改名等实体间编排属业务规则，放 IPC 违反技术栈规范 §2「IPC 禁业务规则」。故新增写路径编排服务，偏差记录。

3. **`saveFixedDef` 部分更新容缺省**：kind/targetCount/weekdayMask 省略时沿用现值（初版必填 kind 导致只改名调用被拒，测试暴露）；note 显式传 null 才清空；改名同步「本周」可注入 today（防测试墙钟漂移）。
4. **`flowVoucherRepo` 初版曾有一处脏代码**（findActiveCheck 误写三元链），自查发现即刻重写为直查实现。
5. **测试基座升级**：node:sqlite 默认 `foreign_keys=ON`（better-sqlite3 默认 OFF，生产由 connection.ts 显式开启——两环境 FK 语义一致，好事），故 `resetDb` 先 `PRAGMA foreign_keys=OFF` 再清库；事务 shim 用真实 BEGIN/COMMIT/ROLLBACK（非 planSync 的 no-op 版），使「写库中途失败回滚零脏数据」可测。
