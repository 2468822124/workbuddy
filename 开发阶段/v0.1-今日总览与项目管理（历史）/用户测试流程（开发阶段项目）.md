## B. 安装与首启（真实交付路径）

### B1. 运行安装包
1. 双击 `E:\workspace\workbuddy\dist\WorkBuddy-Setup-0.1.0.exe`。
2. **SmartScreen 弹窗**（蓝色「Windows 已保护你的电脑」）→ 点「**更多信息**」→ 点「**仍要运行**」。
   > 这是预期行为（应用未签名），不是病毒。
3. NSIS 安装向导 → 「下一步」→ 安装目录保持默认（或自选）→ 「安装」→ 「完成」。
   > 不需要管理员密码；安装到当前用户目录。

**✅ 应看到**：安装完成，桌面出现 `WorkBuddy` 快捷方式。

**❌ 失败现象**：
- SmartScreen 没出现「更多信息」（先点一下弹窗空白处展开）
- 安装中途报错 / 卡死
- 安装完没有快捷方式

### B2. 首次启动
1. 双击桌面 `WorkBuddy` 快捷方式。
2. 首次进入「今日总览」——**内容基本是空的**（正常，还没配置）。
3. 顶部应有非阻塞提示条「欢迎使用 WorkBuddy ☀ 前往设置配置你的 AI 与称呼」，右侧「知道了」按钮。

**✅ 应看到**：窗口正常显示；今日总览有 5 个卡片格子（今日待办 / 今日热点 / 交接事项 / 今日灵感空态 / 昨日复盘空态）+ 顶部问候 Hero。

**❌ 失败现象**：
- 提示条是挡住全屏的弹窗（应为非阻塞条）
- 窗口崩 / 白屏

**→ 测完 A + B，进入配置阶段 C。**

## C. 晨间唤醒 + 今日总览（产品灵魂）

### C1. 配置基础信息
1. 点左侧「**设置**」。
2. **通用**：称呼填你的名字（如「锋哥」）→ 点「保存」。
3. 晨间时段保持默认 `06:00–09:00`（或改成现在所在时段，方便测晨间触发）。
4. 点顶部提示条「知道了」关掉它。

**✅ 应看到**：保存后回到「今日总览」，Hero 问候变成「早安/午安/晚安，锋哥」。

**❌ 失败**：问候没变化 / 称呼没保存。

### C2. 拉取热点
1. 今日热点卡右上角点刷新图标 ⟳（或 Hero 的「刷新热点」按钮）。
2. 等 2–5 秒。

**✅ 应看到**：今日热点卡出现 3–5 条新闻（36氪 / 少数派 / V2EX 源），每条有源名 + 标题 + 日期。点任一条 → 用系统浏览器打开原文。

**❌ 失败现象**：
- 显示「暂无更新，点击重试」且一直如此（可能源被墙，报我）
- 点新闻不跳转 / 在应用内打开
- 一直转圈不出

### C3. 待办卡 + 响应式计数
1. 今日待办卡底部输入框 → 输入「测试待办1」→ 回车。
2. 再加「测试待办2」「测试待办3」。
3. 看卡片标题旁的计数「已完成 0 / 3」。
4. 点「测试待办2」前的方框勾选。

**✅ 应看到**：勾选后该条划除变灰；计数实时变「已完成 1 / 3」（**必须立即变，不用刷新**）；取消勾选 → 回到 0 / 3。

**❌ 失败**：计数不动 / 要刷新才变 / 划除动画异常。

### C4. 交接事项（需昨日待办）
> 这个要造一个「过期待办」才能测。较繁琐，可选。
1. 进「项目」→ 建一个项目「测试项目」→ 进详情页 → 加一个 todo，计划日期选**昨天**。
2. 回「今日总览」→ 交接事项卡应出现这条。
3. 点该条「加入今日」。

**✅ 应看到**：该条从交接卡消失，出现在今日待办卡，计数 +1。

**❌ 失败**：交接卡不显示 / 点「加入今日」无反应。

### C5. 空态卡
- 「今日灵感」「昨日复盘」两张卡应显示「敬请期待 / 即将上线」空状态。

**❌ 失败**：报错 / 白块。

## D. 项目管理 + todos

### D1. 建项目
1. 左侧「项目」→ 新建项目「WorkBuddy 测试」，描述随便填。
2. 看板视图应出现该项目卡（默认「进行中」列）。
3. 切换「列表视图」→ 应能切回。

**✅ 应看到**：项目创建成功，两种视图都正常。

### D2. 建 todo（带计划日期）
1. 进项目详情页 → 任务列表 → 新建 todo「写测试报告」，计划日期选**今天**。
2. 再建一个「调研竞品」，计划日期选**今天**。

**✅ 应看到**：详情页任务列表出现两条。

### D3. 流入总览
1. 回「今日总览」。
2. 今日待办卡应出现「写测试报告」「调研竞品」两条（与 D2 同步）。

**❌ 失败**：总览不显示项目里的 todo（数据流断了，报我）。

### D4. 勾选 + 计数
1. 在总览勾选「写测试报告」。
2. 计数应变「已完成 1 / N」。
3. 回项目详情页，该 todo 也应是已完成态。

**❌ 失败**：总览和详情页状态不同步。

### D5. 软删除
1. 项目详情页删一个 todo（应有「确认删除」类二次确认，软删除）。
2. 列表里消失，但**不应物理报错**。
3. （进阶，可跳）用 SQLite 工具查 todos 表，该条 `isDeleted=1` 还在。

**❌ 失败**：删除报错 / 没有确认直接删 / 应用崩。

## E. 设置 + 测试连接 + 数据管理

### E1. AI 配置 + 测试连接（三态）
1. 「设置」→ AI 配置：
   - Base URL：如 `https://api.deepseek.com`
   - Model：如 `deepseek-chat`
   - API Key：你的 Key
2. 点「**测试连接**」。

**✅ 三种预期**：
- 配置正确 → 几秒内显示「连接成功，XXms」
- 故意填错 Key → 显示「API Key 无效或已过期」之类（**不能卡死**）
- 故意填一个不存在的 URL → 显示「连接超时」或「连接失败」（**应在 10 秒内返回**，不无限转）

**❌ 失败**：转圈超过 10 秒 / 成功也不返回 / 失败时崩。

### E2. 导出
1. 「设置」→ 数据管理 → 「导出」。
2. 系统保存框 → 选个位置 → 存为 `workbuddy-backup-xxx.json`。
3. 用记事本打开该 JSON 确认里面有 projects / todos 等数据。

**✅ 应看到**：JSON 文件生成，内容含你建的待办项目；**API Key 不应在明文里**（llmApiKey 是密文或不在导出内）。

**❌ 失败**：导出失败 / 含明文 Key（安全漏洞，必报）。

### E3. 导入（round-trip）
1. **先记下当前数据**（几个待办）。
2. 「设置」→ 数据管理 → 「导入」→ 选刚才的 JSON。
3. 应有**内联二次确认**「将覆盖现有全部业务数据」（不是系统弹窗 alert/confirm）→ 确认。
4. 导入完成 → 显示导入条数。

**✅ 应看到**：数据与导出时一致（项目/todo 都回来）。

**❌ 失败**：导入报错 / 数据丢失 / 用了系统模态弹窗（应为内联确认）。

### E4. 首启不再显示
1. 完全关闭 WorkBuddy（任务栏右键退出）。
2. 重新打开。
3. 顶部「欢迎使用」首启条**应不再出现**（因为 E1/B1 配置过 → onboarded=true）。

**❌ 失败**：首启条又出现。

## F. 对话式热点搜索（LLM）

> **需 E1 已配好可用 LLM 才能测 F2。没 Key 可只测 F1（降级态）。**

### F1. 未配 LLM 的降级态
> 若 E1 已配 Key，可临时清空 Key 保存来测此态，或跳过。
1. 设置里把 API Key 清空保存（或用全新未配置状态）。
2. 回今日总览，看今日热点卡底部「问问 Agent」搜索条。

**✅ 应看到**：搜索条灰色禁用，显示「配置 AI 后即可对话搜索」+「**去设置**」按钮；点「去设置」跳到设置页；**输入框打不了字、不发请求**。

**❌ 失败**：能输入 / 点了发请求 / 「去设置」不跳。

### F2. 正常对话搜索
1. 重新填回正确 Key（E1）保存。
2. 回今日总览（如搜索条仍禁用，刷新一下页面 / 重开应用——配置变更后需重新探测）。
3. 搜索条输入「今天有什么科技新闻？」→ 回车（或点发送）。
4. 等 5–20 秒。

**✅ 应看到**：
- 显示「Agent 思考中…」加载态
- 出现一段中文回答 + 下面 1–5 条「引用结果卡」（带源名/标题/一句相关性）
- 点任一引用卡 → 系统浏览器打开该新闻原文
- 右上「×」可清除结果

**❌ 失败现象**：
- 一直转圈超 30 秒不返回
- 返回空白 / 报错红条（红条是降级，算正常处理但报我看错误文字）
- 点引用卡不跳转
- 回答里出现乱编的链接（不应有，链接应来自本地缓存）

### F3. 错 Key 降级
1. 设置里把 Key 改成错的（如 `sk-wrong`）保存。
2. 回总览再问一个问题。

**✅ 应看到**：搜索卡内出现**红色状态条**「API Key 无效或已过期…」+「重试」按钮（**不是系统弹窗，不崩**）。

**❌ 失败**：崩 / 卡死 / 弹系统报错框。

## G. 降级与边界

### G1. 断网降级
1. **断开网络**（关 WiFi / 拔网线）。
2. 点今日热点卡刷新。

**✅ 应看到**：保留上次的热点缓存（不空白）；显示「暂无更新，点击重试」；**不崩、不无限重试**。恢复网络后再点刷新 → 正常拉取。

**❌ 失败**：热点全消失 / 一直自动重试卡死 / 崩。

### G2. 数据库密文验证（重要安全项）
1. 关闭 WorkBuddy。
2. 按 `Win+R` → 输入 `%APPDATA%\workbuddy` → 回车。
3. 应看到 `workbuddy.db` 文件。
4. （进阶，可跳）用任意 SQLite 查看器（如 DB Browser for SQLite）打开它 → 查 `settings` 表 → 找 `llmApiKey` 行。

**✅ 应看到**：`llmApiKey` 的 value 是**密文乱码**（不是你的明文 `sk-xxx`）。

**❌ 失败**：value 是明文 Key（安全漏洞，必报）。或 DB 文件不在 `%APPDATA%\workbuddy\workbuddy.db`（路径漂移）。

### G3. 单实例
1. 双击桌面 WorkBuddy 快捷方式打开。
2. **再双击一次**快捷方式（试图开第二个）。

**✅ 应看到**：不开第二个窗口；已有的窗口被聚焦/从最小化恢复。

**❌ 失败**：开了两个窗口（会导致 SQLite 写冲突，报我）。

### G4. CSP（进阶，可选）
> 仅当你愿意开开发者工具时测。
1. 在 WorkBuddy 窗口按 `Ctrl+Shift+I`。
2. 若被自动关闭（打包态 devtools 守卫）→ 跳过此项（守卫正常）。
3. 若能打开 → 看 Console 标签页。

**✅ 应看到**：无红色 `Content Security Policy` 违规警告（黄色警告可忽略）。

**❌ 失败**：有红色 CSP 违规阻断（Google Fonts/脚本被拦）。

## H. 性能

### H1. 冷启动
1. 完全退出 WorkBuddy。
2. 掐表 → 双击快捷方式 → 到窗口可操作（能点侧边栏）。

**✅ 应看到**：< 3 秒。

**❌ 失败**：> 5 秒 / 一直白屏。

### H2. 内存占用
1. 打开 WorkBuddy，停在今日总览**闲置 30 秒**（不操作）。
2. `Ctrl+Shift+Esc` 开任务管理器 → 找 `WorkBuddy.exe`（可能有多个进程，看最大的那个）。

**✅ 应看到**：主进程内存 < 150 MB（Electron 多进程，看最高的那个工作进程，正常 80–150 MB）。

**❌ 失败**：单进程 > 250 MB（内存泄漏，报我）。
