## 5. 核心设计

### 5.1 晨间唤醒触发（`services/morning.ts`）
```
maybeRunMorningRoutine():
  today = 当前 'YYYY-MM-DD'
  last  = settings.get('lastMorningRoutine')?.value
  若 last === today → 返回（今日已跑）
  nowMin = 当前 HH:MM
  若 not (morningStart <= nowMin <= morningEnd) → 返回（非晨间时段）
  # 执行：
  await news.refreshNews()              # 拉取+缓存热点
  settings.set('lastMorningRoutine', today)
  mainWindow.webContents.send('morning:done')
```
- 在 `main/index.ts` 的 `app.whenReady` 内、`createWindow()` 之后异步调用（**不阻塞窗口显示**）。
- 交接事项不需"预处理"——渲染层实时查 `todos:overdue`。

### 5.2 RSS Provider 抽象（`services/rss-provider.ts`）
```ts
export interface NewsItem {
  id: string          // sha1(link) 作主键
  title: string
  link: string
  source: string      // 源名，如 "36氪"
  sourceId: string    // 源 id，如 "36kr"
  summary: string | null
  publishedAt: string | null  // ISO
}
export interface NewsProvider {
  id: string; name: string; type: 'rss'; url: string
  fetch(): Promise<NewsItem[]>
}
```
- `RssProvider.fetch()`：`new Parser({ timeout: 6000, headers: { 'User-Agent': 'WorkBuddy/0.1' } })` → `parseURL(url)` → 映射字段（`isoDate || pubDate` → publishedAt；`contentSnippet` → summary）。若某源 403/超时/格式错 → `throw`，由聚合层捕获。

### 5.3 聚合 / 去重 / 缓存（`services/news.ts` + `newsRepo.ts`）
```
refreshNews():
  providers = JSON.parse(settings.get('newsProviders').value)   // 阶段1已seed
  results = await Promise.allSettled(providers.map(p => new RssProvider(p).fetch()))
  items = results.filter(fulfilled).flat()
  newsRepo.upsertMany(items)        # INSERT ... ON CONFLICT(link) DO NOTHING（去重）
  settings.set('lastNewsFetchAt', now); settings.set('lastNewsFetchOk', 有任意成功)
  发送 'news:updated' 事件
  return { count: 新增条数, cached: false }
getNews(limit=5):
  SELECT * FROM news_items ORDER BY publishedAt DESC LIMIT ?
```
- **单源失败不阻塞其他源**（allSettled）。
- **全失败**：保留旧缓存，`lastNewsFetchOk=false`，UI 显示重试提示。
- **缓存优先**：渲染层 `news:list` 立即返回缓存，后台刷新完通过 `news:updated` 事件触发重取。

### 5.4 交接扫描
复用阶段 1 `todoRepo.findOverdue(today)`（`planDate < today AND status='todo' AND isDeleted=0`）。「加入今日」→ `todoRepo.update(id, { planDate: today })`。

## 6. 数据模型变更（migration `0002_news_items.ts`）
```sql
CREATE TABLE IF NOT EXISTS news_items (
  id TEXT PRIMARY KEY,           -- sha1(link)
  title TEXT NOT NULL,
  link TEXT NOT NULL UNIQUE,
  source TEXT NOT NULL,
  sourceId TEXT,
  summary TEXT,
  publishedAt TEXT,
  fetchedAt TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_news_published ON news_items(publishedAt DESC);
```
- 注册到 `migrate.ts` 的 migrations 数组：`{ version: 2, name: '0002_news_items', up: init002 }`。
- **`news_items` 为缓存表，豁免 §9 软删除**：仅 upsert（`ON CONFLICT(link) DO NOTHING`），**不自动物理删除**；未来如需清理须显式设计并评审。本阶段保留全部。
- settings 复用：`lastMorningRoutine`（阶段1已seed）、`morningStart/End`（已seed）、`newsProviders`（已seed）；新增读写键 `lastNewsFetchAt`、`lastNewsFetchOk`（按需写入，不 seed）。

修复 GLM 审查（审查日志/阶段2.md）指出的 4 个问题：F1 事件通知链断裂、F1b newsOk 语义、F2 预载类型、F3 死代码。

## 修复明细

### F1 [MED] + F1b — 后台刷新通知链断裂 + newsOk 语义错误
- **文件**：`services/news.ts`, `services/morning.ts`, `composables/useToday.ts`
- **改法**：
  - news.ts: 新增 `sendNewsUpdated()` helper，`refreshNews()` upsert 完成后调用，`getMainWindow().webContents.send('news:updated')`
  - morning.ts: 移除 `morning:done` 发送 + `getMainWindow` 导入（刷新通知统一由 refreshNews 内部发）
  - useToday.ts: `newsOk` 改读 `lastNewsFetchOk` 设置值（`loadAll` 和 `loadNews` 回调内），全失败时 newsOk=false → 热点卡显示「暂无更新点击重试」
- **验证**：grep 确认 `news:updated` 在 news.ts:12 发送；build ✅

### F2 [LOW] — preload news.list 类型
- **文件**：`preload/index.ts`
- **改法**：`Promise<Result<unknown[]>>` → `Promise<Result<NewsItem[]>>`，加 `NewsItem` import
- **验证**：build ✅；去除 useToday 的 `as NewsItem[]`（类型直接一致）

### F3 [LOW] — MORNING_STATUS 缺 inWindow + 死 code
- **文件**：`ipc/news.ipc.ts`, `composables/useToday.ts`
- **改法**：
  - news.ipc.ts: MORNING_STATUS 补算 `inWindow`（nowMin 与 morningStart/End 比较）
  - preload/index.ts: 返回类型加 `inWindow: boolean`
  - useToday.ts: 移除 `morningWindow` ref（模板未用）+ 相关 `morningStart/End` 异步取
- **验证**：build ✅；`useToday` 返回对象不再含 `morningWindow`
