## 5. 核心设计

### 5.1 electron-builder.yml（新建，逐字段实现）
```yaml
appId: com.workbuddy.app
productName: WorkBuddy          # ⚠️ 写在此文件，勿入 package.json（见 5.2 userData 路径稳定性）
artifactName: WorkBuddy-Setup-${version}.${ext}

directories:
  output: dist                  # 安装包输出（与 electron-vite 的 out/ 区分）

files:
  - out/**/*                    # electron-vite 产物（main/preload/renderer）
  - package.json

asar: true
asarUnpack:                     # ⚠️ 关键坑：native 模块必须解包出 asar
  - '**/better-sqlite3/**'
  - '**/*.node'

win:
  target:
    - target: nsis
      arch: [x64]
  # icon: build/icon.png        # 提供则用，缺失回落 electron 默认（不阻塞构建）

nsis:
  oneClick: false               # 标准安装向导（可选目录）
  perMachine: false             # per-user 安装（%LOCALAPPDATA%，无需管理员/UAC）
  allowToChangeInstallationDirectory: true
  createDesktopShortcut: true
  createStartMenuShortcut: true
  shortcutName: WorkBuddy

# 未签名：不配置 win.certificateFile / signtoolOptions
```
> **asar 解包**：electron-builder 默认会对 `*.node` 解包；此处显式 `asarUnpack` better-sqlite3 整包，**双保险**防止 `.node` 被打进 `app.asar` 导致运行时找不到 native 二进制。验收见 §9 #11。

### 5.2 ⚠️ userData 路径稳定性（关键坑，勿踩）
- `app.getPath('userData')` = `%APPDATA%/<app.getName()>/`；`app.getName()` 默认取 `package.json` 的 `name` 字段（当前 = `workbuddy`）。
- **若把 `productName: WorkBuddy` 写进 `package.json`**，则 `app.getName()` 在打包后返回 `WorkBuddy` → userData 路径漂移到 `%APPDATA%/Workbuddy/` → 与既有 dev 数据库/设置不一致。
- **对策**：`productName` 只写 `electron-builder.yml`（影响安装包名/开始菜单/显示名），**不动 `package.json` 的 `name`**。`app.getName()` 保持 `workbuddy`，DB 路径稳定 `%APPDATA%/workbuddy/workbuddy.db`。
- 验收：打包后首启，DB 文件出现在 `%APPDATA%/workbuddy/workbuddy.db`（非 `Workbuddy`）。

### 5.3 package.json 脚本（新增）
```jsonc
"scripts": {
  "dev": "electron-vite dev",
  "build": "electron-vite build",
  "preview": "electron-vite preview",
  "rebuild": "electron-rebuild -f -w better-sqlite3",
  "pack:win": "electron-vite build && electron-builder --win --x64 --dir",   // 解包目录，快速验证启动（不产出安装包）
  "dist:win": "electron-vite build && electron-builder --win --x64"          // 出 NSIS 安装包
}
```
- `pack:win`（`--dir`）产出 `dist/win-unpacked/WorkBuddy.exe`，**双击可直接运行**——用于在打安装包**之前**先验证 better-sqlite3 native rebuild 是否成功（启动不崩 = rebuild 成功）。这是 §9 风险「打包易翻车」的最快反馈回路。
- `dist:win` 产出 `dist/WorkBuddy-Setup-0.1.0.exe`。

### 5.4 生产加固（`src/main/index.ts`，全部 `app.isPackaged` 守卫）
```ts
import { app, BrowserWindow, Menu, session } from 'electron'

// (1) 单实例锁 —— 必须在 app.whenReady 之前调用，防 SQLite 双开写冲突
const gotLock = app.requestSingleInstanceLock()
if (!gotLock) { app.quit() }
else {
  app.on('second-instance', () => {
    const wins = BrowserWindow.getAllWindows()
    if (wins.length) wins[0].isMinimized() && wins[0].restore(); wins[0].focus()
  })

  app.whenReady().then(async () => {
    // (2) 仅打包态加固
    if (app.isPackaged) {
      Menu.setApplicationMenu(null)                              // 移除默认 File/Edit/View 菜单
      // CSP 头注入（renderer 从 file:// 加载；dev 不受限以保 HMR）
      session.defaultSession.webRequest.onHeadersReceived((d, cb) => {
        cb({ responseHeaders: { ...d.responseHeaders, 'Content-Security-Policy': [
          "default-src 'self'",
          "script-src 'self'",
          "style-src 'self' 'unsafe-inline' https://fonts.googleapis.com",
          "font-src 'self' https://fonts.gstatic.com data:",
          "img-src 'self' data: https:",
          "connect-src 'self'",
          "object-src 'none'",
          "base-uri 'self'"
        ].join('; ') } })
      })
    }
    // ... 既有 initDb / runMigrations / seedDefaults / registerAllIpc / createWindow / maybeRunMorningRoutine
  })
}
```
- **devtools 守卫**（在 `window.ts` createWindow 内，`app.isPackaged` 时）：
  ```ts
  if (app.isPackaged) {
    mainWindow.webContents.on('devtools-opened', () => mainWindow?.webContents.closeDevTools())
  }
  ```
- **CSP 说明**：renderer 仅外联 Google Fonts（index.html `<link>`）；RSS/LLM fetch 全在主进程（不受 renderer CSP 约束），故 `connect-src 'self'` 即可。`script-src 'self'`（Vue 构建抽 JS 到文件，无需 'unsafe-inline'）；`style-src 'unsafe-inline'`（Vue 运行时可能注入内联样式，保留以稳）。
- **单实例**：第二实例启动 → 聚焦已有窗口 + 退出新进程；杜绝两个进程同时开同一 SQLite（WAL 读并发尚可，但写竞争会报错 → 单实例根治）。

**DeepSeek 在项目日志/当前状态.md 称**：复跑受阻于「Electron/Windows bug #49034」，建议用户 `npm ci` 重装依赖。

**GLM 实测纠正**：阻塞的真正原因是环境变量 **`ELECTRON_RUN_AS_NODE=1`**（headless agent harness 注入），它使 electron 退化为纯 node 进程、不加载 Electron API → `require('electron')` 返回 npm 包 `index.js` 的 exe 路径字符串 → `electron.app` undefined。

**教训**：headless 环境跑 Electron 失败时，先查 `ELECTRON_RUN_AS_NODE` / `process.versions.electron`，勿先归因上游 bug。
