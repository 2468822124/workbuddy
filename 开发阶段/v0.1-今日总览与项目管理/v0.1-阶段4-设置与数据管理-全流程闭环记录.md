## 5. 核心设计

### 5.1 AI 配置与测试连接（`services/llm.ts`）
```
testConnection(cfg: {baseUrl, model, apiKey}): Promise<LlmTestResult>
  - 规范化 baseUrl：去尾部斜杠，拼 '/chat/completions'
  - 请求体：{ model, messages:[{role:'user',content:'ping'}], max_tokens:1, stream:false }
  - 头：{ 'Authorization': 'Bearer <apiKey>', 'Content-Type': 'application/json' }
  - AbortController 超时 10s
  - 200 → { ok:true, latencyMs }
  - 非 200 / 网络错 / 超时 → { ok:false, message }（message 不含 apiKey；超时提示「连接超时(>10s)」）
  - **禁记录 apiKey**：logger 仅记 status / message（redact 已覆盖，但此处显式不传入）
```
> §9 token 红线：用户主动触发（foreground），不适用；且 `max_tokens:1` 极小。

### 5.2 数据导出/导入（`services/data.ts`）
**导出**：
```
exportAll(): 调 dialog.showSaveDialog(defaultName=workbuddy-backup-YYYYMMDD.json)
  → 用户选路径后，组装 payload：
    { version:1, exportedAt:ISO, tables:{ projects:[...], todos:[...], settings:[...],
      inboxes, plans, templates, reviews, notes, books, workout_logs } }
  → 逐表 SELECT * （业务表白名单 10 个；**跳过 news_items 缓存 + __schema_migrations 元表**）
  → fs.writeFile UTF-8 JSON（pretty，2 空格）
  → 返回 { ok:true, path } ；用户取消 → { ok:false, message:'cancelled' }
```
**导入**：
```
importAll(): 调 dialog.showOpenDialog(filters=[json])
  → 读文件 → JSON.parse → 校验：
      必须有 version(number) 与 tables(object)
      tables 仅含白名单 10 表，每表为 row 对象数组
      校验失败 → 返回 err，**不动 DB**
  → 通过后 db.transaction 内逐表：DELETE FROM <table>（白名单，防注入）→ INSERT 每行
      （列名取 Object.keys(row)，占位符按列数；全用 bound param）
  → 任意异常 → 事务回滚，返回 err，**现有数据不损坏**
  → 成功 → 返回 { ok:true, counts:{projects:n, todos:n, ...} }
  → 重新 seedDefaults 不覆盖已有（与阶段1一致）；导入后设置项以导入为准
```
> **§9 豁免声明**：导入是**用户主动全量恢复**路径（数据恢复，与 §9 模态例外同源），物理替换表内容（DELETE+INSERT）而非软删除。仅由用户在 UI 明确触发（文件选择 + 内联二次确认）。`news_items` 不导入（可由晨间重新拉取）。

### 5.3 热点源编辑（HotspotSourcesEditor）
- 读 `newsProviders`（JSON 数组 `{id,name,type:'rss',url}`）→ 列表行（name + url + 删除）。
- 新增行：name/url 输入 + 添加（id 用 `randomUUID` 或时间戳 slug；url 需 http(s):// 校验）。
- 编辑：行内改 name/url。
- 保存：前端重组数组 → `settings:set('newsProviders', JSON.stringify(arr))`。
- 「立即刷新热点」按钮 → 调 `news:refresh`（阶段 2 通道）。

### 5.4 设置页结构（SettingsView）
单页滚动，分节（每节 BaseCard）：
1. **通用**：称呼（nickname 文本）、晨间时段（morningStart/morningEnd，`<input type="time">`）。保存按钮。
2. **AI 配置**：Base URL、Model（文本）、API Key（password 输入，密文存）、「测试连接」按钮（未填 baseUrl/model 时禁用 + 提示）。保存 + 测试分开。
3. **热点源**：HotspotSourcesEditor + 「立即刷新」。
4. **数据管理**：导出按钮 / 导入按钮（导入前内联二次确认「将覆盖现有全部业务数据」）。

### 5.5 首启引导完整化
- SettingsView 保存「称呼」或「AI 配置」成功后，调 `settings:set('onboarded','true')`。
- 阶段 1 首启条 `isFirstLaunch` 据此判断 → 配置过即不再显示。

## 10. 禁止边界 & 错误降级（承袭并具化）
- **§9 日志**：`llm:test` 严禁记录 apiKey；错误仅记 status/message（redact 兜底 + 显式不传入）。
- **§9 token 红线**：测试连接为用户主动触发（foreground），`max_tokens:1`；红线不适用。
- **§9 软删除豁免**：导入为用户主动全量恢复路径，物理 DELETE+INSERT 替换业务表，已显式声明豁免；`news_items` 不导入。
- **导入失败降级**：事务回滚 + 非阻塞错误提示，现有数据不损坏。
- **无应用模态弹窗**：文件选择用 OS 原生 `dialog`（非应用模态，必需）；覆盖确认用**内联二次确认**，禁 alert/confirm。
- **输入校验**：baseUrl 需 http(s)://；model 非空；provider url http(s)://；前端拦截 + IPC 复校。
- **无硬编码 hex**：复用 tokens.css。
- **XSS**：所有用户输入（baseUrl/model/provider name）渲染用 `{{}}`，禁 v-html。
