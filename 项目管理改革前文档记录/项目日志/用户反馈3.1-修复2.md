## 缺陷概要

**根因**：`pickTask` 选取即 `await markTaskConsumed` 写库——单向、无回滚。用户选取「周任务1」进草稿（未保存）→ 切换页面丢弃草稿 → weekly_plan 残留 `[x]`（幽灵消耗）+ rail 永久隐藏 → 用户判断 4：**任务未完成却消失且在周统筹标记完成 ❌**。

**方案 C（用户锁定）**：消耗跟随 todo 完成（非选取）。选取/保存均不标 `[x]`；仅 todo 勾选完成才标 `[x]`，取消勾选回 `[ ]`。**无 schema 变更，规格语义变更**。

## 关键决策

| 项 | 取舍 | 原因 |
|---|---|---|
| 消耗触发语义变更 | 选取→隐藏 → **todo 完成→[x]** | 方案 C（用户锁定）：最贴反馈3.1 原话「选取并完成」——关键在「并完成」 |
| `[x]` 逆操作先不从 IPC 调，直接内联 | todos.ipc.ts 内直接做文本替换 | 减少跨 IPC 调用；逻辑简单且己有 TASK_OPEN_RE/TASK_CONSUMED_RE 可用；PLAN_MARK_TASK_UNCONSUMED IPC 保留供未来外部调用 |
| 多日同名去重 | 仅 `findByContentInRange` 按 content 文本 + 周范围去重 | todo 无 planId 列；文本+周范围匹配同 `syncPlanTodos`/`markTaskConsumed` 既有先例 |
| weekly→monthly 级联 | **out-of-scope**（本反馈仅 daily↔weekly） | §7 明确「控制范围；未来 CR」 |
| 日计划 `[ ]` 不随 todo 完成勾选 | **既有缺陷，不在 C 范围** | `syncPlanTodos` 不回写 daily_plan；§7 明确「另行立案」 |
| §6 遗留 8.15 weekly 脏值 | 不变 | 已记录 |
| W33 周任务1 已是 buggy `[x]` 幽灵值 | 不自动清；用户可周统筹手动改回 `[ ]`，或建同名 todo 取消勾选触发逆操作 | 用户数据只读原则 |

### 规则3 行为变化（须告知用户，§7 已记录用户接受）
C 下，周任务仅在「本周某日 todo 已完成」后才在后续日 rail 隐藏。**保存但未完成期间，该任务在所有日 rail 仍可见、可被多日选取**，直到某天完成才消失。
