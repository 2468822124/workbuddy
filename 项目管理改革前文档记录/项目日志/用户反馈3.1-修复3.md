## 缺陷概要

方案 C 核心（todo↔weekly 完成同步）经用户 E2E 验证成立；本轮为两处 UX 细化缺陷，**同源：pickTask 末尾盲追加 + rail 隐藏源仅会话级**：

- **F3-1.3-A（rail 保存后复现，🟡）**：选取→pendingHide 会话级隐藏→保存落库→切日→load() 清空 pendingHide→返回该日 planDraft=savedPlan（含任务）但 rail 只判 `!consumed && !pendingHide.has` → weekly 仍 `[ ]`（todo 未完成）→ **rail 复现已保存任务**。
- **F3-1.3-B（任务错位「备注」段，🟡）**：模板任务段（`## ✅ 任务清单`/`## ✅ 本周任务`/`## ✅ 本月任务`）在中段、备注在末尾；pickTask 末尾盲追加 → 新任务落到备注段之后。syncPlanTodos 解析全文档 `- [ ]` 行不分段故 **todo 仍正确生成（非数据错误）**，但视觉错位。

**修复方向（GLM §9 指定）**：rail 隐藏源从会话态 pendingHide 改为 **planDraft 内容派生**（inDraftTexts，覆盖全场景，pendingHide 可移除）；pickTask 改**插入任务段**（非末尾盲追加），找不到段回退末尾 + warn。方案 C 的 todo↔weekly 完成同步（§7 Req5-7）**不动**。

## 关键决策/取舍

| 项 | 取舍 | 原因 |
|---|---|---|
| inDraftTexts 派生 vs 保持 pendingHide | 派生（GLM 指定）：覆盖保存后跨日场景，pendingHide 会话级无法表达「已保存但未完成」第三态 | §9 诊断「缺第三态」 |
| renderer 侧正则复用 | 用 usePlanning 既有 `TASK_LINE_RE`（与 planParser TASK_STATE_RE 同形），不 import main 侧 planParser | renderer 不可跨进程 import main；避免新增 shared 导出扩大改动面 |
| fallback 日志 | `console.warn`（renderer 无 logger 工具） | GLM §9 明确要求 warn；main 侧 logger 不变 |
| 插入点 | 段内末个任务行之后（段内无任务行→下一 `##` 前） | §9「末个 `- [ ]` 之后、或下一 `##` 之前」原文 |
| 段标题匹配 | `^#{2,}\s` + `includes('任务')` | 三模板标题 `✅ 任务清单`/`✅ 本周任务`/`✅ 本月任务` 均命中；不含「任务」的自定义段不误插 |
| 保留 pickTask 末尾 `loadParentTasks` | 不删 | 刷新 consumed 状态（既有行为）；rail 隐藏已不依赖它 |
| 方案 C todo↔weekly 同步 | **不动** | §9 约束「§7 Req5-7 不动」 |
