## 4. ⚠️ 纠正 DeepSeek 的「#49034」误诊（重要）

**DeepSeek 在项目日志/当前状态.md 称**：复跑受阻于「Electron/Windows bug #49034」，建议用户 `npm ci` 重装依赖。

**GLM 实测纠正**：阻塞的真正原因是环境变量 **`ELECTRON_RUN_AS_NODE=1`**（headless agent harness 注入），它使 electron 退化为纯 node 进程、不加载 Electron API → `require('electron')` 返回 npm 包 `index.js` 的 exe 路径字符串 → `electron.app` undefined。

- 这是**确定性环境变量**问题，**不是**间歇性 Electron bug。
- **用户的真实 Windows 11 机器无此变量**（用户 08-06 dev 日志已到 `WorkBuddy starting...`，证明其 `electron.app` 正常）。
- 解开 `unset ELECTRON_RUN_AS_NODE` 后，GLM 成功实跑并通过全部运行时验收（见 §2 #4/#5）——**DeepSeek 本可自行验证，但因误诊放弃**，仅做了构建层核查。
- **用户无需 `npm ci`/重装依赖**。DeepSeek 写给用户的复测指引（「重装依赖」「Electron/Windows bug #49034」）基于错误根因，应忽略——用户直接 `npm run dev` 或重装安装包即可。

**教训**：headless 环境跑 Electron 失败时，先查 `ELECTRON_RUN_AS_NODE` / `process.versions.electron`，勿先归因上游 bug。
