## F3-1 日规划页串档加载周模板/周复盘 — 🔴 真实缺陷（HIGH）

### 用户报告
- **场景 C**：打开**日规划**界面
  - **预期**：显示「日模板 + 可选周任务（CascadeRail）+ 日复盘」
  - **实际**：显示「**周计划模板** + 无周任务 + **周复盘**（AI 生成的周复盘模板）」
- **场景 D**：在**周统筹**区输入周任务（月任务同理）
  - **预期**：周任务掉入日规划中的「本周周任务」侧栏（CascadeRail）
  - **实际**：周任务掉入日规划中**错误存在的周模板区**（编辑器被周计划内容占位），且日规划中的「本周周任务」侧栏**未见任何信息**
- **是否报错**：否
- **截图**：3 张（已附）。关键证据：页面头部「规划明日 2026-08-09」（daily 的 panelTitle，正确），但编辑器是「周计划·{{week}} / 本周重点{{focus}} / 本周任务 / 分日安排 / 备注」且含用户刚写的「周任务A / 周任务B」；右侧 CascadeRail「本周周任务」0 可选、为空。

### 环境
- **模块**：规划页 `/planning/:level`（PlanningView.vue + planning/ 子组件）
- **触发条件**：同一应用会话内**先后打开不同 level**（如先开周统筹、再开日规划）。
- **影响**：**核心功能完全错乱**——日/周/月三级内容互相串档；级联 CascadeRail 数据源 level 错（取不到上级任务或取错上级）；模板/复盘 type 错。**阻断场景 C/D/E（确定性回顾、级联点选回写、runSync 门控观察）全部无法正确实测**。

### GLM 诊断（代码逐行核实）
**裁定：🐛 真实缺陷。根因 = vue-router 组件复用 + PlanningView setup 内 level 派生量在 setup 时冻结。**

**机制**：
1. `/planning/:level` 的 daily/weekly/monthly 三级**共用同一个 PlanningView 组件实例**（vue-router 默认行为：同组件不同路由参数 → 复用实例，**不重新执行 setup**）。
2. PlanningView.vue 在 setup 顶层（**一次性求值**）捕获了 level 派生量：
   - `src/renderer/src/views/PlanningView.vue:26` `const plan = usePlanning(level.value)`
   - `src/renderer/src/views/PlanningView.vue:27` `const planType = LEVEL_TO_PLAN_TYPE[level.value]`
   - `src/renderer/src/views/PlanningView.vue:28` `const reviewType = LEVEL_TO_REVIEW_TYPE[level.value]`
   - （`level` 本身是 computed，line 22-24，会随 `props.level` 响应更新）
3. 切换 level（如周统筹→日规划）时：`level.value` 更新（故 `panelTitle`「规划明日」、`periodLabel`、`role-tag` 等**用 computed/props 的 UI 是对的**），但 `planType`/`reviewType`/`plan` 这三个**常量/闭包冻结在首次打开的 level**。
4. 后续 `load()` 用冻结的 planType/reviewType 去查：`api.plans.getByPeriod({type: planType,...})` / `api.reviews.byDate(curStart, reviewType)` / `api.templates.list(planType)` → **加载到首次 level 的模板/计划/复盘**。

**与截图完全吻合**：用户先开周统筹 → planType 冻成 `weekly_plan`、reviewType 冻成 `weekly_review`、`plan`=usePlanning('weekly') → 再开日规划 → panelTitle 显示「规划明日」（daily 的 computed，正确）→ 但 `load()` 仍按 weekly 取 → 编辑器 = 周计划模板（含用户刚写的周任务A/B），复盘区 = 周复盘，CascadeRail 因 `plan.loadParentTasks` 内 `PARENT_LEVEL[冻结的weekly]='monthly'` 去取月任务（空）→「本周周任务」侧栏空。

**为何 GLM 03 静态审查未发现**：headless 无法实跑 Electron GUI 做跨 level 切换；逐文件读码时这三行看似正确（单次进入某 level 时逻辑无误），组件复用导致的「冻结」是运行时行为，静态读不出来。属规格 §11 明示的「用户 E2E 实跑」待验项。

### 推荐修复（供 DeepSeek 04 参考，DS 定最终实现）
**首选方案（最小、标准、低风险）**：在 `<router-view>` 上按 `route.path` 作 key，强制切换 level 时重建 PlanningView，setup 重跑 → planType/reviewType/usePlanning 用新 level 重新求值。
- 文件：`src/renderer/src/components/AppLayout.vue`
- 改法：`<router-view />` → `<router-view :key="route.path" />`，并在 `<script setup>` 引入 `import { useRoute } from 'vue-router'` + `const route = useRoute()`。
- **务必用 `route.path` 而非 `route.fullPath`**：PlanningView 的期切换（`‹ ›`）走 `router.replace({ path, query: { date } })`（PlanningView.vue watch curStart，line 127-130），date 在 query 里。用 `path` 作 key：daily/weekly/monthly 不同 path → 重建（✓ 修复）；date query 变化（同 level 内翻期）→ path 不变 → 不重建（✓ 不丢草稿、不重复 mount，由既有 watch+load 处理）。若误用 `fullPath`，每次翻期都会重建组件，是回归。
- 影响面：WorkBuddy 其他路由（/today、/projects/:id、/settings）path 各异，key=path 对它们无副作用（切换本就换组件）。

**备选方案（更侵入，不推荐）**：把 PlanningView 内 `planType`/`reviewType` 改为 `computed`，`usePlanning` 改为接受响应式 level（内部所有用 `level` 处改 `.value`/watch）。改动面大、易引入新问题，不建议。

**验证点（DS 修后 GLM 复审 + 用户复测）**：
- [ ] 同一会话：周统筹→日规划→月指导→日规划，每级都显示**本级正确模板 + 本级复盘 + 本级 CascadeRail 标题**。
- [ ] 日规划 CascadeRail 显示「本周周任务」（非空，当本周有 weekly_plan 时）；周统筹显示「本月月任务」。
- [ ] 日规划保存生成待办、周/月不生成（runSync 门控，场景 E）。
- [ ] 翻期（‹ ›）不重建组件、不丢草稿（确认 key 用 path）。

### 严重度
🔴 **HIGH** —— 核心功能串档，阻断子阶段5 主要验收点（C/D/E）实测。**必须修**。

## F3-3 「浏览器在哪」— ✅ 非缺陷（GLM 实测指南措辞错误）

### 用户报告
- **场景 A**：用户按 GLM 实测指南「浏览器地址栏手动改 `#/plan` 回车」操作 → 问「浏览器在哪？」

### GLM 诊断
**裁定：✅ 非缺陷——是 GLM 实测指南（本轮对话）的措辞错误，不是应用 bug。**

- WorkBuddy 是 **Electron 桌面应用，没有浏览器地址栏**；路由用 `createWebHashHistory`（hash 路由），`#/plan` 这种 URL 在 Electron 窗口里用户看不到、也无处手输。
- **路由重定向本身静态已验证正确**（GLM 03 审查）：`src/renderer/src/router/index.ts:29-30` `{ path:'/plan', redirect:'/planning/daily' }`、`/review` 同。这两条旧路由仅为向后兼容（老书签/老链接），**不是用户日常入口**（日常入口是侧栏「规划」树），用户无需手动测。
- **若一定要实测重定向**（可选）：dev 模式下按 `Ctrl+Shift+I` 开 DevTools → Console 执行 `location.hash = '#/plan'` 回车 → 页面应跳到 `/planning/daily`（日规划）。

**处置**：澄清即可，**无需 DS 改代码**。本轮 GLM 实测指南该条措辞作废，已在此更正。

— （非缺陷）
