## F3.2-1 日规划删任务 → 今日总览待办未删除 — 🟡 spec 合规 vs 期望冲突（CR）

### 用户报告
- **现象**：8.7 日规划删「测试3」→ 日规划正常删（✔）→ **今日总览（8.8）仍显示测试3**（❌）。
- **用户隐含期望**：日规划删一个任务 → 对应今日总览待办同步删除（删除传播）。

### GLM 诊断（代码实锤，未改任何代码）
**裁定：⚠️ 当前 spec 合规（子阶段2「残留不删」设计），但与用户期望冲突 → 建议作 CR 改删除语义。**

**机制（`planRepo.ts:151-207` syncPlanTodos）：**
- 保存日计划 → 解析当前 `- [ ]` 任务（`parsed`）→ 复用/新建 todo（`resultIds`）→ 残留 todo（`oldIds` 不在 `resultIds`）= `orphanTodoIds`（L195）。
- **orphan todo 不软删**（L195 仅 `filter` 返回供 UI 提示，**不置 isDeleted=1**）→ 今日总览（按 `isDeleted=0` 查，`todoRepo.findToday`）仍显示。
- UI 提示（`PlanningView.vue:168-169`）：`ℹ️ N 条任务已移出计划，对应待办仍保留` ← 系统**已告知「仍保留」**，但用户期望「删除」。

**非 F3-1.x 回归**：F3-1.x 全是**级联**（rail/pick/consume/placement）；本项是 syncPlanTodos **删除传播**，机制独立。子阶段2 既定「残留不删」（F4 LOW 仅涉 orphan 计数精度，非删除本身）——**spec 合规，非 bug**，但用户期望与之冲突 → CR。

**DS 须真实 DB 核实**：用户删测试3后是否保存？查 `%APPDATA%/workbuddy/workbuddy.db` todos 表 `content='测试3'` 的 `isDeleted`/`planDate` + plans 表 `generatedTodoIds` 归属，确认走 orphan 路径（已保存）vs 未保存路径（plan 仍含测试3）。两种路径 todo 都会留在今日总览，但修复点不同。

### 修复方向（CR，需用户定方案）
| 方案 | 行为 | 取舍 |
|---|---|---|
| **A 软删全 orphan** | 保存时 orphan todo 全 `isDeleted=1` | 最简单，符用户期望；但**临时删行再加回 → 完成态丢失**（syncPlanTodos 按 content 复用，软删后不复用→新建） |
| **B 软删 open orphan（GLM 倾向）** | orphan 中 `status='todo'` 软删；`status='done'` 保留（历史） | 符期望 + 保留已完成历史；略复杂（syncPlanTodos 加状态判断） |
| **C 保持现状 + UI 强化** | 不改删除，今日总览 orphan 标「已移出计划」+ 可手动删 | 零数据风险；但用户仍见「残留」直到手动清 |

> GLM 倾向 **B**（open 删、done 留）。**需用户拍板** A/B/C。定后 DS 实现（改 syncPlanTodos + 提示文案 + 回归测试）。

### 严重度
🟡 **MED** —— 破坏「删除」心智模型，但**非数据错误**（反而是数据保留过度）。spec 合规故非回归；CR 级。

### 3.1 F3.2-1 方案 B（软删 open orphan，留 done）
**改 `planRepo.syncPlanTodos`（planRepo.ts:194-196）：**
- 现状：`orphanTodoIds = oldIds.filter(x => !resultIds.includes(x))` → 仅返回，不软删。
- 改：遍历 `orphanTodoIds` → `todoRepo.findById` → `status='todo'` → `todoRepo.softDelete(id)`；`status='done'` → 保留。分别计 `removedOpenCount` / `keptDoneCount`。
- 提示文案（PlanningView.vue:168-169）改：`ℹ️ {removedOpen} 条未完成已随计划删除移除；{keptDone} 条已完成保留为历史`。
- **不动手动 todo**：B 只处理「该 plan 生成过、现被删行」的 orphan（oldIds 差集）；手动 quickCreate todo 从不在 oldIds → 不受影响（归用户手清）。

**回归测试（tests/ 新增）：** ① 删 open→todo 消；② 删 done→todo 留；③ 删 done 后重新加回同文本行→复用保留完成态（reuse pool `!isDeleted`，done 未软删故命中）；④ 删 open（已软删）后加回→新建 todo='todo'。

### 3.2 F3.2-2 Tier 2（sourcePlanId 列 + 出处标注，最细粒度）
