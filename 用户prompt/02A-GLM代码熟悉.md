# 用户 Prompt · 02A GLM 代码熟悉（一次性只读）

> **用途**：GLM 首次承担 WorkBuddy 代码任务前，建立可复核的仓库、架构、边界和当前状态认知。
> **执行者**：GLM。
> **维护方**：GPT。
> **性质**：一次性只读熟悉，不是实现、修复、审查或验收，不打开 `02/04/07/08` 的代码执行门。
> **固定根目录**：文档根 `E:\workspace\`；代码根 `E:\workspace\workbuddy\`。

## 使用条件

- 只在 GLM 第一次执行代码任务前使用一次；后续任务直接按适用的 `02`、`04`、`07` 或 `08`。
- GPT 仍负责项目管理、规格、治理、独立审查和门禁裁决；GLM 与 DS 是现行代码执行团队。
- DS 既有实现事实、历史日志和历史署名保持原样；本 Prompt 不把历史 DS 工作改记为 GLM。

## 严格只读边界

1. 允许使用 `rg`、文件查看命令和只读 `git status/log/diff --stat` 了解结构与工作树。
2. 不修改、创建、删除或重命名任何代码、测试、配置、数据库、构建物、治理文档、Prompt、状态看板或证据文件。
3. 不安装依赖、不运行会写入工作树或数据目录的脚本；不执行迁移、重置、清理、提交、切换分支、格式化或网络操作。
4. 不把代码阅读推断写成测试通过、审查通过、用户验收或 `C0/QA/S/C1` 结论；发现冲突只记录为待核对项。
5. 当前工作树已有的用户或其他执行者改动必须原样保留，不能为了熟悉而清理或回退。

## 必读文件

按以下顺序读取，并在输出中逐项列出实际读取结果：

1. `E:\workspace\AGENTS.md`
2. `E:\workspace\工作流.md`
3. `E:\workspace\当前代码状态.md`
4. `E:\workspace\当前审查状态.md`
5. `E:\workspace\文档索引.md`
6. `E:\workspace\规范类\文档治理总纲.md`
7. `E:\workspace\规范类\阶段闭环门禁规则.md`
8. `E:\workspace\规范类\技术栈规范.md`
9. `E:\workspace\规范类\命名规则.md`
10. `E:\workspace\规范类\git提交规范.md`
11. `E:\workspace\workbuddy\package.json`、锁文件和 `tsconfig*.json`

然后根据 `当前代码状态.md`、`当前审查状态.md` 和当前任务指针，读取对应的现行项目计划、全流程闭环文档底部最新正式结论、实现/修复日志和测试计划。历史目录只作背景，不改写、不当作当前门禁。

## 熟悉任务

### 1. 仓库与工作树

- 确认文档根/代码根、当前分支、HEAD、工作树是否有未归属变化，以及哪些目录属于历史冻结区、构建产物或真实用户数据边界。
- 列出当前任务可能涉及的代码、测试、构建和配置入口；不要假定文件名或目录状态。

### 2. 架构地图

用自己的话说明 `main/db/repositories`、`main/services`、`main/ipc`、`preload`、`renderer`、`shared` 和 `tests` 的职责、单向依赖和禁止越层。
明确 SQL、迁移、IPC `Result<T>`、数据派生、软删除、错误反馈和敏感数据的约束。

### 3. 两条代表性数据流

只读追踪至少两条当前代码中真实存在的链路：

- 一条从 Vue 页面/组件经过 composable、preload、IPC、service、repository 到 SQLite；
- 一条与当前状态看板所述任务或最近 Fix 直接相关的查询、写入、派生或错误路径。

为每条链路列出实际文件、关键函数/通道、输入输出和可能的失败降级；不要修改任何文件。

### 4. 工具与验证入口

记录项目已有的测试、构建、类型检查和 Electron/GUI 入口，以及哪些验证只能由 GPT 或用户执行。区分“可运行命令”和“本次熟悉实际运行过的命令”；本 Prompt 默认不运行构建或测试。

### 5. 当前状态与缺口

分别列出：

- 已验证事实（来自文件或只读命令）；
- 待补证据/冲突（不能自行裁决）；
- 需要 GPT 在具体规格中明确的输入；
- 不能带入本次任务的越界范围。

## 固定输出格式

完成后只返回一份熟悉报告，不写入文件：

1. 已读取文件清单；
2. 当前分支、HEAD、工作树和数据隔离事实；
3. 架构地图；
4. 两条数据流追踪表；
5. 验证入口与禁止边界；
6. 已验证事实 / 待核对项 / 需要 GPT 明确的输入；
7. **熟悉结论**：`只读熟悉完成，未执行代码修改，未形成审查或验收结论`；
8. 等待 GPT 提供具体开发单元、绝对路径、批准文件范围和适用 Prompt。

不要声称“代码已通过”“可以直接发布”或“任务已完成”。
