# 用户 Prompt · 07 DeepSeek 修复用户反馈（给 DeepSeek）

> **用法**：用户实测报问题 → GPT 在 `用户实测阶段/` 创建全流程闭环记录并给出诊断 + 修复计划后，把本文件复制粘贴给 **DeepSeek**。替换 `{{用户反馈N}}` 为实际反馈编号（如「用户反馈1」）。
> **与 04 的区别**：04 修的是构建期审查问题（落 `开发阶段/`）；**07 修的是用户实测反馈**（落 `用户实测阶段/`，修复依据是用户在真实环境撞出的问题）。

---

你是 DeepSeek。GPT 已在 `用户实测阶段/vX-{功能名}-实测/vX-用户反馈{N}-{简述}-全流程闭环记录.md` 录入用户实测反馈，并给出**诊断 + 修复计划**（文档内对应环节）。请按修复计划逐条修复。

**权威依据（按优先级）**：
1. 该反馈全流程闭环记录的「修复计划」环节（**唯一修复依据** —— 改什么、file:line、验收点）
2. 该反馈「诊断」环节（根因，理解为什么这么改）
3. `用户测试流程.md`（用户原始测试步骤，确认修复后能过该步）
4. `规范类/命名规则.md`（命名）
5. `规范类/技术栈规范.md`（**修复代码强制遵守**：分层边界/数据层铁律/目录落位；违规修复即使功能通过也打回）
6. `当前代码状态.md`（当前任务状态）

**约束**：
- **只修「修复计划」环节指出的问题**，不得扩大范围、不得擅自重构未要求的部分。
- 主修复 + 列出的附带加固项都要做；不在计划的 不改。
- 任何偏差/取舍在 `当前代码状态.md` 记录原因。
- **复跑用户原始失败场景**（反馈「复现步骤」环节 + 用户测试流程对应步骤），确认修复后通过；**不能只查代码**（教训：headless 代码核查会漏运行时 bug）。

**记录义务（缺一不可）**：
1. 在 `用户实测阶段/vX-{功能名}-实测/vX-用户反馈{N}-{简述}-全流程闭环记录.md` 内**续写「DeepSeek 修复」环节**（按 `模板/04_反馈部分/用户实测反馈部分编写模板.md` 的「修复记录」格式）——写清改了什么文件、为什么、对应修复计划哪条。**不再使用 `项目日志/` 文件夹。**
2. 同文档更新「闭环记录」环节（DeepSeek 修复轮 → 结论 + 日期；门禁状态 🛠→ 待复审）。
3. 更新 `当前代码状态.md` 的当前任务信息（修复摘要、影响范围、用户复测所需信息）。

**完成后报告**「用户反馈{N} 修复完成，待复测」，告诉我：
- 改了哪些文件（对应修复计划哪条）；
- 复跑用户失败场景的结果（如 `npm run dev` 现在能否开窗、cmd 有无报错）；
- 用户该如何复测（给具体命令/操作）。

我会据此用 **05 prompt（GPT 复审）** 或直接让用户复测。
