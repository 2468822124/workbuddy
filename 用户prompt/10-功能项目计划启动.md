# 用户 Prompt · 10 功能项目计划启动（给 GLM）

> **用法**：**新功能立项时**（如知识库 / 运动 / 灵感速记等全新功能），把本文件复制粘贴给 **GLM**。这是新功能的**第一步，先于 01–05 子阶段循环**。
> **产出物**：功能级 `项目计划.md`，指导整个功能的实现路径（子阶段划分 / 功能级验收·边界 / 版本规划）。
> **与 01 的区别**：**10 产出功能级项目计划**（整个功能一份，含子阶段划分）；**01 产出子阶段级规格**（写进各子阶段全流程闭环记录的「规格」环节）。即 10 规划"功能怎么拆"，01 落实"每个子阶段怎么做"。

---

你是 WorkBuddy 的项目经理 GLM。现在立项新功能 **{{功能名}}**，请产出功能级项目计划。

**权威依据（按优先级）**：
1. 用户口述的功能需求（本 prompt 附带的描述）
2. `项目管理改革前文档记录/开发阶段项目计划/项目计划.md` §7（验收标准 / 禁止边界 / 错误降级三表 —— **项目级上位基准**）
3. `项目管理改革前文档记录/开发阶段项目计划/规格-阶段0-视觉.md`（视觉基准，涉及 UI 时）
4. `规范类/命名规则.md`、`规范类/文档治理总纲.md §2`（双根）、`规范类/阶段闭环门禁规则.md`
5. `规范类/技术栈规范.md`（**技术选型与架构设计强制基准**：新功能的技术设计/数据模型/依赖引入必须符合；需要新依赖时按规范 §8 评审流程写入计划，禁止计划中预设未评审依赖）
6. `当前代码状态.md`（项目现状，避免与在研功能冲突）

**产出要求**：
1. 先建功能目录 `开发阶段/v{{X}}-{{功能名}}/`（命名遵守 `规范类/命名规则.md`）。
2. 在该目录下产出 `项目计划.md`，用 `模板/01_计划部分/项目计划部分编写模板.md`，按**功能级粒度**填写（非子阶段粒度）。
3. 必须含：
   - **功能目标**（一句话可演示价值 + 用户可见成果）
   - **子阶段划分**：列出每个子阶段的 `{{unit}}` / `{{unit名}}`（这是后续 01–05 循环的工作单位）；明确各子阶段边界，避免范围重叠
   - **子阶段依赖关系**（先后顺序、哪些可并行）
   - **功能级验收点 / 禁止边界 / 错误降级**（承袭上位 §7 三表并按本功能场景具化）
   - **版本规划**（目标版本号，如 v0.3.0）
4. 规格精确到 DeepSeek 无需再问即可实现；命名遵守 `规范类/命名规则.md`；文档操作回**文档根**（双根规则）。

**完成后**：
- 告诉我「{{功能名}} 项目计划已就绪，划分 N 个子阶段：{{unit列表}}」。
- 我会据此：
  1. 在 `00-开发单元闭环Prompt使用说明.md §三` 旁追加本功能的**占位符替换表**（`{{计划目录}}` = `开发阶段/v{{X}}-{{功能名}}`、各子阶段 `{{unit}}`/`{{unit名}}`）；
  2. 用 **01 prompt** 逐子阶段启动开发单元闭环（01 的规格写进各子阶段的**全流程闭环记录**文档）。

> 注：项目计划.md 是功能级**活文档**（常驻 `开发阶段/vX-功能名/`，不归档）；只有当功能全部子阶段闭环并验收后，才随功能归档。
