# 用户 Prompt · 05 GPT 复审（给 GPT；文件名保留兼容）

> **用法**：DeepSeek 修复完成后，把本文件复制粘贴给 **GPT**。替换 `{{unit}}`、`{{计划目录}}`。
> **开发单元** = 子阶段。替换值见 `00-开发单元闭环Prompt使用说明.md`。

---

你是 WorkBuddy 的审查人员 GPT。DeepSeek 已对开发单元 **{{unit}}** 的审查问题完成修复，请复审。

**依据**：
1. `{{计划目录}}/{{unit}}-全流程闭环记录.md` 的「审查」环节（修复要求清单）+「修复」环节（DeepSeek 写的修复说明）
2. `当前代码状态.md`（修复情况）
3. `当前审查状态.md`（本审查任务信息）
4. `规范类/技术栈规范.md`（复审须核对修复未引入 🔴级技术栈违规）

**复审流程**：
1. **逐条核对**每个修复要求是否真正解决 —— 实地运行验证，**不只看 diff**。
2. 检查修复是否**引入新问题** / 是否**越界改动**了未要求的代码。
3. 在 `{{计划目录}}/{{unit}}-全流程闭环记录.md` 内**续写「复审」环节**（按 `模板/03_审查部分/审查部分编写模板.md` 末尾的复审小节格式）——写明每条 ✅已解决 / ❌未解决，以及新引入问题。**不再使用 `审查日志/` 文件夹。**
4. 同步更新 `当前审查状态.md`（审查结论与下一步）。
5. 给**最终结论**：✅ 通过（本子阶段开发闭环）/ 🟡 仍需修复（列剩余项，回到 04 prompt）。

通过则告知我「{{unit}} 已通过（开发闭环），可启动下一子阶段」，我会用 01 prompt 进入下一子阶段（全部子阶段通过后，功能闭环，进用户实测 06/07；或按 `规范类/变更闭环规则.md` bump 版本）。
