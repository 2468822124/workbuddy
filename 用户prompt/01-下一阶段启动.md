# 用户 Prompt · 01 开发单元启动（给 GPT&Claude）

> **用法**：上一个开发单元（子阶段）通过后，把本文件复制粘贴给 **GPT&Claude**。替换 `{{unit}}`、`{{unit名}}`、`{{计划目录}}`、`{{prev}}`。
> **前置**：功能须已用 **10 prompt** 立项并产出 `{{计划目录}}/项目计划.md`（功能级，含子阶段划分）。01 是该功能下**单个子阶段**的启动。
> **产出物**（改革后）：**不再产出独立规格文件**，而是把规格写进本子阶段的**全流程闭环记录文档**的「规格」环节。

> **阶段门禁卡**：开启条件 = `10` 项目计划已登记、目标子阶段和路径唯一、上一子阶段（如有）底部最新正式结论与当前指针均为 `✅开发闭环`；完成状态 = 规格写入唯一全流程文档，`planStatus=ready`、`closureStatus=in-progress`、`nextAction=02`；失败回退 = 计划/路径冲突回 `10`，上一阶段未闭环回对应 `04/05`，用户强制跳过必须留痕并由用户承担风险。更新时间和证据写入启动卡。

你是 WorkBuddy 的项目经理 GPT&Claude。现在进入开发单元 **{{unit}} — {{unit名}}**（功能目录 `{{计划目录}}/`）。

## ⛔ 前置闭环检查（启动规格前必须执行）

进入新开发单元前，**必须先确认上一开发单元（`{{prev}}`）已 ✅ 开发闭环**（见 `规范类/阶段闭环门禁规则.md`·前置闭环检查条款）：

1. 读 `当前审查状态.md` 的当前指针和「关联文档」→ 定位上一开发单元（`{{prev}}`）的全流程闭环记录。
2. 查该全流程记录**底部最新正式结论**，并与当前指针核对；顶部状态只作历史元信息：
   - **✅ 开发闭环** → 正常继续，编写本单元规格。
   - **🟡待审 / 🟡实现中 / 🔴需修复** → **上一单元未闭环**：
     - **先提醒用户**：「`{{prev}}` 尚未闭环（最新正式结论/门禁：{状态}），建议先完成闭环（用 04 修复 → 05 复审）再进入 `{{unit}}`。」
     - 若用户**执意要求**进入：在 `当前审查状态.md` 的当前快照中覆盖写入「⚠️ 用户要求跳过 `{{prev}}` 闭环进入 `{{unit}}`」（含未闭环项 + 门禁状态 + 日期），并在本单元全流程记录「规格」环节顶部标注「⚠️ 前置 `{{prev}}` 未闭环」，然后继续；不得在当前状态文件末尾追加日期章节。

首单元（`{{prev}}` = 无）跳过本检查。

依据以下文件，在本子阶段全流程闭环记录内编写「规格」环节：
- `{{计划目录}}/项目计划.md`（功能级计划 —— 本子阶段的范围/边界/验收由它划定；看其子阶段划分与本 unit 的对应）
- `{{计划目录}}/{{prev}}-全流程闭环记录.md`（上一子阶段的闭环记录，确认前置已 ✅；首子阶段 `{{prev}}` = 无）
- `项目管理改革前文档记录/开发阶段项目计划/项目计划.md`（项目总规划上位；§7 验收/禁止边界/降级三表）
- `当前代码状态.md` + `当前审查状态.md`（项目现状）
- `规范类/技术栈规范.md`（**技术栈与分层边界**——规格中的技术设计、数据模型、IPC、目录落位必须符合本规范，违规设计不得写入规格）
- `项目管理改革前文档记录/初级文档/`（v0.3 原始定义，必要时回查）

**产出要求**：
1. **创建/打开本子阶段全流程闭环记录文档**：`{{计划目录}}/{{unit}}-{{unit名}}-全流程闭环记录.md`（命名遵守 `规范类/命名规则.md`；若功能目录下已有命名惯例则对齐）。
2. 在文档内**编写「规格」环节**，按 `模板/01_计划部分/项目计划部分编写模板.md` 格式书写。必须含：
   - 单元目标 / 范围(含与不含) / 前置依赖 / 技术设计 / 数据模型变更 / IPC 契约 / 任务拆解(有序) / 验收点(可勾选可验证) / 禁止边界与错误降级(承袭并具化)。
3. 文档现行元信息填「当前门禁状态」栏（见 `规范类/阶段闭环门禁规则.md`）：本子阶段初值 `🟡实现中`，并同时记录 `planStatus=ready`、`staticGate=not-applicable`、`testPointStatus=not-applicable`、`closureStatus=in-progress`、`updatedAt`、`updatedBy=GPT`、`evidence` 和 `nextAction=02`。
4. 规格精确到 GLM+DS 无需再问即可实现；命名遵守 `规范类/命名规则.md`；文档操作回**文档根**（双根规则，见 `规范类/文档治理总纲.md §2`）。GLM 首次参与代码执行时，先完成一次 `02A-GLM代码熟悉.md`。

**完成后**告诉我「{{unit}} 规格已就绪（写入全流程闭环记录，待 02 执行）」并报告启动状态、完成时间和下一步；我会转交 GLM+DS 执行（用 02 prompt；GLM 首次执行前先用 02A）。
