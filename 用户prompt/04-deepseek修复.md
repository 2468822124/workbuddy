# 用户 Prompt · 04 DeepSeek 修复（给 DeepSeek）

> **用法**：GLM 审查结论为「需修复」时，把本文件复制粘贴给 **DeepSeek**。替换 `{{unit}}`、`{{计划目录}}`。
> **开发单元** = 子阶段。替换值见 `00-开发单元闭环Prompt使用说明.md`。

---

你是 DeepSeek。GLM 在本子阶段全流程闭环记录的「审查」环节给出了结论：🟡 需修复。请按审查记录中的「发现的问题 / 修复要求」**逐条修复**。

**权威依据**：
1. `{{计划目录}}/{{unit}}-全流程闭环记录.md` 的「审查」环节（GLM 写的修复要求清单 —— **唯一修复依据**）
2. `当前代码状态.md`（当前任务状态）
3. `当前审查状态.md`（GLM 审查要求与重点）
4. `规范类/技术栈规范.md`（**修复代码同样强制遵守**：分层边界/数据层铁律/目录落位；修复方案若与规范冲突，停下提出 CR 而非违规实现）

**约束**：
- 只修审查指出的问题，**不得扩大范围、不得擅自重构**未要求的部分。
- **每条修复在 `{{计划目录}}/{{unit}}-全流程闭环记录.md` 内续写「修复」环节**（按 `模板/02_日志部分/项目日志部分编写模板.md` 格式）——写清：改了什么文件、为什么、对应审查问题 #。**不再使用 `项目日志/` 文件夹。**
- 更新 `当前代码状态.md` 的核心字段（当前状态/任务概要/自测结果/已知问题/下一步）。
- 重新自测所有受影响的验收点，结果写进「修复」环节的自测表。
- 偏差/取舍同样在 `当前代码状态.md` 记录原因。

完成后报告「{{unit}} 修复完成，待 GLM 复审」，我会用 05 prompt 启动复审。
