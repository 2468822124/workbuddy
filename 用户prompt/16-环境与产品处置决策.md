# 16 - 环境与产品处置决策（给 GPT&Claude）

> **用途**：处理 R 闭环中的环境阻塞和需要产品选择的事项。GPT&Claude 负责证据、影响、选项、用户决定和后续计划的记录；GPT&Claude 不替用户作产品决策，16 不修改代码、数据库、测试计划或状态文件。
>
> **前置关系**：13 发现并登记事项 → 16 完成逐项证据和用户选择 → 13 更新事项处置总表 → 若批准替代/删除且计划齐全，由 GLM+DS 使用 07 在统一 Fix 中执行；若继续排障，事项仍阻断 Fix，直到独立排障完成并重新核对。

> **阶段门禁卡**：开启条件 = 事项已由 13 登记，且同一 S/测试副本/正式入口的最小环境证据可核对；完成状态 = 决策状态、责任人、生效时间、复评时间、用户选择原文、恢复条件和返回阶段齐全；失败回退 = 未决定保持 `⏸️待环境/产品决策` 并阻塞相关 Fix，继续排障回 `16` 复评，替代/删除执行后回 `07 → 05`。

决策生效时间：
复评时间：
恢复条件：
返回阶段：`13 / 07 / 05 / 14`

## 一、读取和唯一性

1. 读取 `规范类/项目代称.md`、`规范类/阶段闭环门禁规则.md`、`用户实测问题全流程闭环模板.md` 和输入 R 文档。
2. 读取该事项对应的测试计划、GPT&Claude 报告、用户 06、用户证据、补充核验证据和当前处置总表；原始事实与用户体验分栏，不凭代码阅读改写。
3. 核对 R 文档唯一性、事项 ID、来源测试点/覆盖缺口、当前 S/测试副本、正式入口和数据隔离。
4. 用户没有明确选择或选择无法定位时，只记录 `⏸️待环境/产品决策`，停止后续 Fix，不替用户补选。

每个事项先建立决策卡：`planStatus`、`staticGate`、`testPointStatus`、`closureStatus`、事项状态、责任人、`updatedAt`、`updatedBy=GPT&Claude`、证据路径和 `nextAction`。`16` 只记录决策，不把环境证据直接改写成产品缺陷或通过。

## 二、环境事项最小证据

每个环境事项必须登记并完成以下最小核对，不能用“无法启动”一句话结束：

1. 在同一 S、同一测试副本下按正式入口重复启动；
2. 记录可核对的进程参数、继承环境变量、实际数据目录、目标窗口和 GUI 结果；
3. 若存在候选替代入口，至少实际验证一个，并分开记录它的入口、进程/环境、数据目录和 GUI 结果；
4. 记录最后成功步骤、可见阻塞、受影响测试点、真实数据风险和是否可安全恢复；
5. 登记排障责任人、独立排障期限、用户/PM 复评点，以及三种决策选项：`继续排障`、`替代`、`删除`。

如果工具或权限导致上述核对无法安全完成，写清已完成的最小核对和具体阻塞，不写产品通过、缺陷已证实或 Fix 可执行。

## 三、产品/环境决策记录

用户必须明确选择以下之一：

- **继续排障**：记录排障任务、责任人、截止日期、复评点、补证步骤和停止条件；事项状态保持 `⏸️待环境/产品决策`，不进入 Fix；
- **替代**：记录被替代入口/行为、批准的新入口/方案、影响范围、迁移/保留边界、实施责任人和验收条件；只有 07 执行并经 05 复审后才完成；
- **删除**：记录批准删除对象、软删除/数据保留或恢复策略、不可逆风险、影响范围、实施责任人和验收条件；只有 07 执行并经 05 复审后才完成。

决策卡必须额外记录：`用户选择`（继续排障/替代/删除/尚未决定）、`生效时间`、`复评时间`、`恢复条件`、`返回阶段`、`closureStatus` 和 `nextAction`。用户未选择时上述字段不能用 GPT 建议代填。

GPT 可以指出风险和建议，但不得把“建议”写成“用户已决定”。用户原文必须单独保留。

## 四、回写和交接

在同一 R 文档追加“环境/产品决策记录”，至少写：

- 事项 ID、来源标签、原始事实、用户主观体验、证据路径和证据等级；
- S/副本/正式入口的最小核对结果；
- 责任人、截止期限、复评点和影响范围；
- 继续排障/替代/删除三选项及用户明确原文；
- 当前决定、后续计划、验收条件和是否仍阻断 Fix；
- 下一步交给 13、07、05 或下一测试计划的路径。

16 不创建 R、测试计划、Fix 或问题 ID，不修改代码、数据库、`当前代码状态.md`、测试计划、GPT 报告或用户 06。若决定替代或删除，后续 14 按新范围编写计划，07 只执行已批准方案；若决定继续排障，复评通过后再由 13 更新事项处置总表。
