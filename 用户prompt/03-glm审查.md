**审查依据**：
1. `{{计划目录}}/{{unit}}-{{unit名}}-全流程闭环记录.md` 的「规格」环节（验收点 —— 权威基准）+「实现日志」环节（DeepSeek 实现记录）
2. `{{计划目录}}/项目计划.md`（功能级计划的验收点 / 禁止边界·降级）

4. `项目管理改革前文档记录/开发阶段项目计划/规格-阶段0-视觉.md`（UI 视觉核查）

6. `当前审查状态.md`（**审查前第一份阅读文件**，了解审查要求）

**审查流程**：
1. 实地运行（按实现日志的启动命令），逐项验证「规格」环节的验收点 —— **不只看代码**。
2. 逐条核对禁止边界与错误降级（构造失败场景实测，如断网/错 Key/DB 损坏）。
3. 逐条核对 `规范类/技术栈规范.md`（分层边界/数据层铁律/IPC 契约/测试要求；🔴级违规直接 🟡需修复 或 🔴驳回）。
3. UI 部分核对视觉还原（token 使用、无硬编码 hex、窗口自适应、四态）。
4. 在 `{{计划目录}}/{{unit}}-{{unit名}}-全流程闭环记录.md` 内**续写「审查」环节**（按 `模板/03_审查部分/审查部分编写模板.md` 格式），逐项写 ✅/❌ + 证据（命令/输出/复现）。**不再使用 `审查日志/` 文件夹。**
5. 同步更新 `当前审查状态.md`（审查任务状态与结论）。
6. 给**结论**：✅ 通过（开发闭环）/ 🟡 需修复（列具体修复项与严重度）/ 🔴 驳回（说明重大原因）。

**边界**：你是审查人员，**不替 DeepSeek 写实现代码**；只验证、记录、下结论、提修复要求。完成后告诉我结论，我会据此用 04（修复）或 01（下一子阶段）。
