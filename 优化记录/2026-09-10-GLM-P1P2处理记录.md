### 1.2 错误复现与根因定位

复现命令 `npm install -D @vitest/coverage-v8@4.1.10` → `npm error Cannot read properties of null (reading 'edgesOut')`，exit 1。

**调试日志**（`C:\Users\lenovo\AppData\Local\npm-cache\_logs\2026-09-10T03_12_04_003Z-debug-0.log`）关键栈：

```
verbose stack TypeError: Cannot read properties of null (reading 'edgesOut')
verbose stack     at #loadPeerSet (...\@npmcli\arborist\lib\arborist\build-ideal-tree.js:1289:38)
verbose stack     at async #buildDepStep (...build-ideal-tree.js:904:11)
```

**根因**：npm 10.9.2 Arborist 构建 ideal tree 时 `#loadPeerSet` 阶段崩溃——日志显示崩溃发生在解析 vitest 4 的可选 peer 依赖图期间（`webdriverio@*`、`puppeteer-core`、`@vitest/browser*`、`happy-dom@*`、`jsdom@*` 等大批 peer manifest 已成功拉取后）。peer 节点放置结果为 null 时该版本 npm 直接抛 TypeError。这是 npm 自身的缺陷类别，**与网络、缓存、registry、项目 lock 均无关**（packument 全部 fetch 成功，配置干净）。GPT 尝试的"清缓存/删 node_modules"两类方案对这类崩溃无效，属预期内。

### 1.3 修复方案与结果

采用 `--legacy-peer-deps`：走旧版 peer 解析路径，完全绕开 `#loadPeerSet` 崩溃点（比升级全局 npm 侵入性小，不改变用户全局环境）：

```bash
npm install -D "@vitest/coverage-v8@^4.1.10" --legacy-peer-deps
# → added 560 packages, audited 561 packages in 1m；EXIT_CODE=0
```

**安装验证**：

```
npm list @vitest/coverage-v8 vitest
├─┬ @vitest/coverage-v8@4.1.11
│ └── vitest@4.1.11 deduped
└─┬ vitest@4.1.11
```

- lock 文件重新生成（lockfileVersion 3）；vitest 与 coverage-v8 解析到同一 4.1.11 版本（`^4.1.10` 语义化范围，对齐无冲突）。

### 1.4 连带发现：`npm ci` 在 CI 上会失败（新增问题 R-1）

P1 完成后按 ci.yml 预检 `npm ci`，发现**两个连锁事实**：

1. `npm ci`（无参数）→ exit 1 EUSAGE"package.json 和 package-lock.json 不同步"。经比对，lock 根节点与 package.json 依赖**完全同步**（程序化 diff = IN_SYNC），该报错信息有误导性；真实原因在警告链中：`@vitest/mocker@4.1.11` 的 peerOptional `vite@"^6.0.0 || ^7.0.0 || ^8.0.0"` 与项目锁定 `vite@"^5.4.0"`（electron-vite 生态）冲突，lock 中留有 INVALID peer 边。
2. 已核实 vitest **4.1.10 与 4.1.11 的 mocker peer 口径完全相同**（npm view 对比），即回钉 4.1.10 无法解决——该地雷在本次事件之前就存在于旧 lock 中，只是从未跑过 `npm ci`/CI。
3. **实证**：`npm ci --legacy-peer-deps` → exit 0（node_modules 由 npm ci 重装，重装后复跑 test:coverage 结果一致）。**CI（ci.yml）的 `npm ci` 需要追加该 flag 才能在远端通过**——ci.yml 在本次禁止修改清单内，留 GPT 决策（改 ci.yml 一行，或在 workbuddy/.npmrc 写入 `legacy-peer-deps=true`）。
