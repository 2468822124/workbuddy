## 三、发现的问题

### P1【阻断覆盖率产出】`@vitest/coverage-v8` 未安装
- **现象**：`npm run test:coverage` → `MISSING DEPENDENCY Cannot find '@vitest/coverage-v8'`，exit 1。
- **根因**：该包不在 package.json devDependencies（node_modules/@vitest/ 下确认无 coverage 包）；执行 Prompt 明令禁止 npm install（"依赖不变"）。
- **影响面**：
  1. 本地无法生成覆盖率报告（`coverage/index.html`、`coverage-summary.json`）；
  2. `tools/track_coverage.py` 无快照可保存；
  3. **CI（ci.yml）的 "Run tests with coverage" 步骤同样会失败**——`npm ci` 只安装 lock 清单内依赖，远端同样缺该包，该 job 将红（后续步骤因无 `continue-on-error` 会中断）。
- **处置**：配置已全部就绪，装包即可用。需用户/GPT 授权执行 `npm i -D @vitest/coverage-v8`（依赖变更，超出本次 Prompt 边界）。**CI 在装包前不宜 push 触发。**

### P2【环境偏差·需用户决策】本机 Node v22.16.0 与声明版本 20.x 不一致
- **现象**：check-env.sh exit 1；本机实际 `node -v` = v22.16.0、npm 10.9.2。
- **影响**：`.nvmrc`/`engines`/CI（20.11.0）均按优化建议报告的口径声明 20.x；本机以 22.16.0 运行全部 404 测试与构建均通过。npm 默认不对 engines 报错（仅警告），本地命令不受阻。
- **需决策**：以声明（20.x）为准则本机需换 Node；以本机（22.x）为准则需改 `.nvmrc`/`engines`/ci.yml/check-env.sh 四处口径。本次按 Prompt 逐字落盘 20.x，未擅自改口径。

### P3【环境偏差·低】Python 3.12.8 ≠ .python-version 声明 3.10.11
- check-env.sh 对 Python 仅警告不退出；两个审计工具在 3.12.8 下实测运行正常。`.python-version` 按 Prompt 落盘 3.10.11。

### P4【工具行为说明】check-env.sh 在 Node 不匹配时提前退出
- Prompt 模板设计为版本不符即 `exit 1`，因此本次 npm/Python/工作目录四项检查未执行到（输出只有 Node 一项）。属模板既定行为，非脚本 bug。

- check-env.sh 的 npm 版本比较用 `bc -l`；本机 `command -v bc` 为空，该分支会把空结果按 0 处理、降级为 ⚠️ 警告（不会误报通过）。本次因 P4 提前退出，未实际走到该分支。
