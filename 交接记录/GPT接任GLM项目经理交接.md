## 2. 项目目标与边界

### 2.1 产品定位

WorkBuddy 是 AI 原生、本地优先的 Windows 桌面个人工作台，技术栈为：

- Electron
- Vue 3
- TypeScript
- better-sqlite3
- Vue Router
- Vitest
- OpenAI 兼容 LLM 接口

当前重构不重新定义整个产品的长期 AI 愿景，而是解决任务数据流通的根本问题。

### 2.2 用户北极星

任务数据像水流：

- 计划按月 → 周 → 日单向下行。
- 完成凭据按任务实例向上汇入。
- 完成态由结构化数据实时派生。
- 改名、删除、完成、撤销和跨页面展示使用同一实体和同一数据源。
- 不依赖文本内容推断任务出处。
- 不通过多份文本和数据库之间的双向同步维持状态。

用户可见目标链路：

周统筹 → 日规划 → 今日总览 → 复盘。

### 2.3 本轮范围

- 结构化任务域和七表基础设施。
- 周统筹页和月目标页。
- 日规划页与 rail。
- 今日总览任务区接入。
- 项目和提醒的适配层。
- 确定性复盘、趋势统计、封账和转下周。
- 阶段 6 路由切换、冻结区清理和全量回归。

### 2.4 本轮明确不做

- 不把 Markdown 或自由文本作为任务域真相源。
- 不从文本匹配、标题匹配或内容去重推断任务关系。

## 3. 架构、数据和接口铁律

### 3.1 数据真相源

结构化数据库是任务域唯一真相源。当前新任务域使用 flow_ 前缀的七类表，承载：

- 固定任务定义。
- 周任务实例。
- 日任务行。
- 完成凭据。
- 月目标。
- 周核心目标。
- 结构化计划模板。
- 叙述域感想单独存储。

具体字段和 DDL 以阶段 1 规格及 0008 迁移为准；未来阶段不得擅自修改已发布迁移脚本。

### 3.2 数据流

计划只向下流：

月目标 → 周核心目标/周任务 → 日任务行。

凭据只向上汇入：

check/manual/extra 等完成凭据 → 任务实例完成态。

完成态、rail、顺延和统计均由查询实时派生，禁止落缓存状态字段。

叙述域感想与任务域物理隔离，不建立文本同步逻辑。

### 3.3 分层接口

渲染层 → preload 桥 → IPC → service → repository。

- renderer 不直连 SQLite。
- preload 只暴露受控桥。
- IPC 负责参数校验、调用 service、Result<T> 包装。
- service 负责业务规则。
- repository 负责 SQL 和行对象映射。
- shared 只放类型、常量和无副作用纯函数。
- 所有 IPC 失败路径必须显式返回 Result<T>，不得静默吞错。

阶段 3 无新增 IPC、迁移和依赖。阶段 4–6 的接口必须在对应阶段规格中冻结，用户确认前不得实现。
