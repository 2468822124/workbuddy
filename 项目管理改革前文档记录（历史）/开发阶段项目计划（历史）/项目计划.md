## 1. 项目概览

**WorkBuddy** —— AI 原生、本地优先的 Windows 桌面个人工作台。核心卖点是「**打开即用的晨间起搏器**」：常驻 Agent 后台主动拉热点、整理交接事项，配合手帐风（温暖、低饱和、大圆角）Bento Grid 界面。

- **技术栈**：Electron + Vue 3 + TypeScript + Vite + better-sqlite3 + OpenAI 兼容 LLM
- **平台**：Windows 11（Day-1 唯一目标）

## 4. 关键技术决策

1. **数据库**：better-sqlite3（主进程同步访问）+ 仓储模式封装；迁移系统（migration）版本化管理 schema。
2. **加密**：API Key 等敏感字段用 Node `crypto` AES-256-GCM 加密；密钥由机器本地秘密派生（不上云、不入库明文）。
3. **RSS 解析**：主进程内用 `rss-parser` 抓取（规避渲染进程 CORS）；失败保留上次缓存（§10）。
4. **热点源抽象**：Provider 接口（RSS / 未来 NewsAPI / 未来 LLM-search 可插拔）；首启预置 RSS 默认源。
5. **IPC**：`ipcMain`/`ipcRenderer` + preload 桥，**强类型通道**，统一错误信封。
6. **LLM**：OpenAI 兼容 Chat Completions；后台自主调用受 §9 token 红线约束，**用户主动触发不限**。
7. **打包**：electron-builder（nsis，Windows x64）；**better-sqlite3 必须 electron-rebuild**（已知关键坑）。

## 5. 默认假设（评审中可纠正）

1. §9「后台单次 >1000 tokens 禁止」**仅约束 Agent 自主后台调用**；用户主动触发（对话搜索等）不限。

3. 全新开始，**不做历史数据迁移**（Obsidian 是独立体系）。
4. 项目看板列 = 进行中 / 已暂停 / 已完成 / 已放弃（沿用 v0.1 定义）。

## 6. 阶段划分（快 / 稳平衡）

### 划分原则
- **先稳地基、再快出旗舰**：把「最易返工」的视觉与工程地基前置（稳），但保持薄（快）；随后尽早交付产品灵魂「晨间唤醒 + 总览」（快），用可见进展维持动力；再逐块补齐；最后谨慎打包（稳）。
- 每阶段都是一个**可评审、可演示**的增量；**质量门禁在前，速度在后**。

| 阶段 | 名称 | 快/稳 | 目标 |
|:---:|---|:---:|---|
| 0 | 视觉地基 | 稳→快 | 锁定手帐风视觉方向，消除「95% 还原度」的最大不确定性 |
| 1 | 工程地基 | 稳 | 薄但正确的 Electron+DB+IPC 骨架，一切依赖它 |
| 2 | 晨间唤醒 + 热点 + 今日总览 | 快 | 交付产品灵魂，打开即用的旗舰体验 |
| 3 | 项目管理（含 todos） | 快 | 闭合数据故事，让总览两张核心卡有真实数据 |
| 4 | 设置 + 数据管理 | 稳 | 打通 LLM 配置入口与备份恢复 |
| 5 | 对话式热点搜索（LLM） | 快 | 兑现「AI 原生」承诺，优雅降级 |
| 6 | 打包 .exe | 稳 | 最终交付，攻克 native rebuild 与安装包 |

### 阶段 0 — 视觉地基（GLM 主导产出）
- **交付**：`视觉规范.md`（色板 / 字体 / 间距 / 圆角 / 阴影 / 图标 token）+ `今日总览-样张.html`（Bento Grid 高保真静态页，含 3 实卡 + 2 空态卡样式）。
- **验收**：用户确认视觉方向；token 可被 Vue 工程直接消费。
- **意义**：先把最「说不清」的视觉钉死，避免 DeepSeek 实现后大面积返工。

### 阶段 1 — 工程地基（DeepSeek 实现 / GLM 评审）
- **范围**：Electron + Vue3 + TS + Vite 脚手架；main / renderer / preload 分层；强类型 IPC 通道 + 错误信封；better-sqlite3 + 迁移系统 + Day-1 schema（projects / todos / settings 为主，inboxes / plans / templates / reviews / notes / books / workout_logs 建表前瞻但 Day-1 不用）；敏感字段加密；手帐风 design tokens 落地 CSS；应用外壳（可折叠侧边栏 + 主内容区 + 路由 + 空状态组件）；首启检测骨架。
- **验收**：dev 冷启动 < 3s；迁移可执行；密文 settings 读写往返正确；IPC 类型安全；视觉与阶段 0 样张一致。

### 阶段 2 — 晨间唤醒 + 热点 + 今日总览（旗舰）
- **范围**：启动触发（时段 06:00–09:00 可配，每日一次）；RSS 多源拉取（Provider 抽象 + 默认源）；交接扫描（`planDate <= 今天` 且未完成）；Bento Grid 3 实卡 + 2 空态卡；交互（交接「加入今日计划」= 改 planDate；待办勾选 + 划除动画；热点点击调系统浏览器；去重）。
- **验收**：晨间数据加载 < 5s；RSS 失败 → 缓存 + 重试卡；无 LLM 亦可运行；§10 热点 / 解析降级行为符合。

### 阶段 3 — 项目管理（含 todos）
- **范围**：项目 CRUD；看板视图（4 列）+ 列表视图切换；详情页（描述 + 任务列表 + 创建 / 编辑 todo 含 planDate）；todo 状态 / 勾选 / 软删除；「关联笔记」→ 敬请期待。
- **验收**：todos 正确流入总览；软删除强制；视图切换无误。

### 阶段 4 — 设置 + 数据管理
- **范围**：API 配置（Base URL / 密文 Key / Model / 测试连接 10s 超时）；热点源增删改；晨间时段配置；JSON 全量导出 / 导入；首启 onboarding 完整化（LLM 引导，非阻塞）。
- **验收**：测试连接 10s 内返回；密钥绝不入日志；导入导出往返一致。

### 阶段 5 — 对话式热点搜索（LLM）
- **范围**：今日热点卡内对话入口；未配 LLM → 禁用 + 提示去设置；已配 → OpenAI 兼容聊天，返回结果卡，点击跳转；token 护栏（前台不限、后台守红线）。
- **验收**：无 LLM 优雅降级；搜索返回卡片并跳转。

### 阶段 6 — 打包 .exe（交付）
- **范围**：electron-builder（nsis, x64）；better-sqlite3 electron-rebuild；生产构建（关 devtools、CSP、最小化到托盘可选）；未签名 + SmartScreen 说明。
- **验收**：见第 8 节端到端验证。

## 7. 评审与质量门禁

每阶段 DeepSeek 提交后，GLM 依下列三张表逐项评审，**全部通过方放行**。

### A. 验收标准（源自 v0.3 §8，已按修订调整）
| 指标 | 目标 |
|---|---|
| 冷启动 | < 3s |
| 晨间唤醒数据就绪 | < 5s（允许骨架屏，禁卡顿） |
| 后台空闲内存 | < 150MB |
| 敏感字段 | 密文存储（整库加密已放宽） |
| Markdown 任务解析 | 标准格式 100%；非标准容错不崩溃（前瞻，Day-1 暂不用） |
| UI 还原度 | ≥ 95%；禁纯黑 #000 / 纯白 #FFF 高对比 |
| API 测试连接 | 10s 内返回结果 |

### B. 禁止边界（v0.3 §9，不可破）
- 日志严禁输出笔记 / 任务明文或 API Key。
- 业务数据严禁上传非用户指定云端（仅系统级 Stack Trace 可报）。
- 后台自主 LLM 单次 ≤ 1000 tokens。
- 删除一律软删除，必须前端用户主动触发。
- 禁模态弹窗阻断（系统级崩溃 / 数据恢复除外）；禁自动播音频视频。

### C. 错误降级（v0.3 §10）
- **LLM 失败**：停止重试防雪崩 + 本地日志 + 模块内红色状态条。
- **热点失败**：保留缓存不阻塞主流程 + 「暂无更新，点击重试」。
- **Markdown 解析异常**：放弃解析保原文（Day-1 暂不用，前瞻）。
- **DB 锁定 / 损坏**：重建连接 → 失败进只读安全模式 + 全局 Toast。
- **热键冲突**：首启提示（Day-1 热键推迟，前瞻）。

## 8. 端到端验证（.exe 交付标准）

在干净 Windows 11 环境：
1. 安装包可正常安装（点过 SmartScreen）。
2. 冷启动 < 3s；晨间唤醒数据 < 5s。
3. 空闲内存 < 150MB。
4. **全流程跑通**：配置 RSS → 晨间拉热点 → 看总览；建项目 → 建 todo（带 planDate）→ 总览出现待办 / 交接 → 勾选完成；配 LLM → 对话搜索 → 跳转；导出 JSON → 重装 → 导入还原。
5. 断网 / 错 Key 降级行为符合第 7-C。
6. 数据库文件中 API Key 为密文；日志无明文敏感数据。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| better-sqlite3 在 Electron 需 native rebuild，打包易翻车 | 阶段 6 单独验证；用 electron-rebuild，本地双跑 |
| 手帐风视觉「95% 还原」主观难评 | 阶段 0 先出 HTML 样张钉死方向 |
| RSS 源失效 / 被墙 | 多源 + 缓存 + 失败降级；默认选国内可达源 |
| DeepSeek 实现偏离规格 | 每阶段 GLM 评审门禁，不通过不进下一阶段 |
| Electron 内存泄漏 | 阶段 6 验收内存 < 150MB；定时任务用单次触发而非长驻轮询 |
