# 个人工作台 Agent - 初始定义文档 v0.2

## 1. 产品概览

### 1.1 产品名称
WorkBuddy

### 1.2 产品定位
AI 原生个人工作台。旨在通过 AI Agent 辅助，为用户提供一个集“晨间唤醒、任务管理、知识沉淀、即时热点”于一体的私密、高效、温暖的工作环境。

### 1.3 核心价值
*   **私密本地优先**：所有核心数据（任务、笔记、配置）均存储于本地 SQLite，保护隐私。
*   **Agent 常驻服务**：后台运行，主动拉取热点、整理交接事项，而非被动等待指令。
*   **手帐式体验**：拒绝冷冰冰的科技感，提供温暖、柔和、结构化的视觉与交互体验。

### 1.4 技术栈
*   **框架**：Electron (主进程作为 Agent 后端)
*   **前端**：Vue 3 + TypeScript
*   **数据库**：SQLite (better-sqlite3)
*   **AI 接口**：兼容 OpenAI 格式的多模型 API

---

## 2. 系统架构设计

### 2.1 进程架构
采用 Electron 多进程模型，实现“Agent 后台化”：
*   **主进程**：充当 **Agent 核心**。
    *   职责：运行定时任务、监听全局热键、调用第三方 API (LLM/新闻)、读写本地数据库、管理配置。
    *   生命周期：随应用启动而常驻。
*   **渲染进程**：UI 界面。
    *   职责：展示 Bento Grid 布局、用户交互、数据可视化。
*   **通信桥梁**：`ipcMain` 与 `ipcRenderer`。
    *   渲染进程发送指令（如“开始复盘”），主进程处理逻辑并返回结果。

### 2.2 数据流向
用户输入 -> 渲染进程 -> IPC -> 主进程 -> 数据库/外部API -> 主进程处理 -> IPC -> 渲染进程更新 UI。

*   `settings`: 系统配置 (API Key, Base URL, 热点关键词)。

## 4. Agent 核心机制

### 4.1 Morning Routine (晨间唤醒)
*   **触发策略**：采用 **启动触发** 模式。
    *   用户每天首次打开应用时，Agent 检测当前时间。
    *   若处于“早晨时段”(如 06:00-09:00) 且今日未触发过，则自动执行 Routine。
*   **执行流**：
    1.  **热点拉取**：根据 `settings` 中预设的关键词，调用新闻 API 获取数据。
    2.  **交接处理**：扫描 `todos` 表，找出 `planDate <= 今天` 且未完成的任务，生成“交接事项”清单。
    3.  **总览渲染**：将热点与交接事项推送到渲染进程，展示在“今日总览”。

### 4.2 API 驱动与兼容性
*   **配置灵活性**：支持接入 OpenAI、DeepSeek、Kimi、通义千问及各类中转站。
    *   **API Base URL**：用户可自定义输入 (如 `https://api.deepseek.com`)。
    *   **API Key**：本地密文存储。
    *   **Model Name**：用户自定义填写 (如 `gpt-4o`, `deepseek-chat`, `qwen-turbo`)。
*   **安全策略**：所有 Key 仅存储于本地，严禁上传云端。

### 4.3 全局灵感速记
*   **触发**：系统级热键 (如 `Ctrl+Shift+N`)。
*   **交互**：
    *   呼起独立的小型悬浮窗。
    *   用户输入内容 -> 回车确认 -> 写入 `inboxes` 表 (`isProcessed: false`) -> 提示“已保存” -> 窗口自动隐藏。

## 5. 功能板块设计

### 5.1 今日总览
采用 **Bento Grid (便当盒布局)**，聚合以下模块：
1.  **交接事项卡片**：展示昨日未完成任务，提示“加入今日计划”。
2.  **今日待办卡片**：今日计划任务，支持直接勾选完成。
3.  **今日灵感卡片**：展示当天 `isProcessed: false` 的灵感速记，点击可处理。
4.  **今日热点卡片**：展示 Agent 抓取的前 3-5 条新闻，点击跳转原文。
5.  **昨日复盘卡片**：简要展示昨天的复盘摘要。

### 5.2 计划与复盘体系
*   **模板驱动**：
    *   进入计划/复盘板块时，Agent 自动拉取对应类型的 `templates`。
    *   根据模板中的占位符 (如 `{{task1}}`)，Agent 发起引导式提问协助用户填写。
*   **自动解析与关联**：
    *   计划保存时，Agent 解析 Markdown 中的 `- [ ]` 任务项，自动写入 `todos` 表。
    *   建立 `plans` 文档与 `todos` 任务的双向关联。

### 5.3 灵感管理
*   **双视图查看**：
    1.  **今日总览**：仅展示今日未处理灵感，强调即时性。
    2.  **知识库-灵感记录**：按日期分组展示所有历史灵感，强调沉淀。
*   **处理动作**：支持“转为待办”、“归档为笔记”、“丢弃”。

### 5.4 项目管理
*   **视图模式**：支持“看板视图” 与“列表视图” 切换。
*   **详情页**：聚合展示项目描述、关联任务列表、关联笔记片段。

### 5.5 知识库
*   **结构分层**：书籍 -> 读书笔记 -> 原子笔记。
*   **双向链接**：
    *   在 Markdown 编辑器中输入 `[[` 触发搜索，链接其他笔记。
    *   笔记底部自动展示“反向链接”列表。

### 5.6 运动记录
*   **录入**：简单表单 (类型、时长、距离、感受)。
*   **趋势**：使用 Chart.js 或 ECharts 展示运动时长趋势，风格保持手帐风（柔和配色）。

### 5.7 今日热点
*   **被动推荐**：Morning Routine 自动抓取。
*   **主动搜索**：对话式搜索，Agent 实时调用 API 返回结果卡片。
*   **交互**：点击卡片调用系统浏览器打开原文，支持简单的去重逻辑。

## 6. UI 视觉规范

### 6.1 色彩规范
*   **背景色**：米白色 (`#FDFCF8`) 或 浅木色 (`#F5F0E6`)。
*   **主色调**：温暖的橙色或陶土色（用于强调按钮、激活状态），避免科技蓝。
*   **文字色**：深灰色 (`#333333`) 代替纯黑，降低对比度刺眼感。

### 6.2 组件风格
*   **圆角**：大圆角 (`rounded-xl` 或 `rounded-2xl`)。
*   **阴影**：柔和的弥散阴影 (`shadow-sm`，颜色偏暖灰)。
*   **字体**：无衬线字体，略微加宽字间距，营造呼吸感。
*   **图标**：建议使用 **Lucide Icons** 或 **Heroicons**，线条圆润，风格统一。

## 7. 设置板块细节

### 7.1 API 配置
*   **API Base URL**：文本输入框，支持用户填写任意兼容 OpenAI 格式的 API 地址。
*   **API Key**：密文输入框，支持任意 Key 格式。
*   **Model Name**：文本输入框，用户自定义模型名称（如 `gpt-4o`, `deepseek-chat`）。
*   **连通性测试**：提供“测试连接”按钮，验证配置有效性。

### 7.2 数据管理
*   **备份/恢复**：支持导出/导入 JSON 格式的全量数据文件。
