# WorkBuddy: 个人工作台 Agent - 初始定义文档 v1.0

## 1. 核心框架与定位
- **产品名称**：WorkBuddy (工作伙伴)
- **产品形态**：Windows 桌面原生应用体验 (基于 Electron)
- **目标用户**：目前供个人使用，未来计划开源至 GitHub。
- **核心场景**：Morning Routine (清早第一件事)。打开即看今日待办与今日热点，作为每日工作流的起搏器。
- **智能层级**：L3-L4 混合。Agent 需具备后台自主规划与主动执行能力 (如主动拉取热点)，而非被动等指令。
- **产品基调**：WorkBuddy 而非冷冰冰的工具，是陪伴者。

## 2. 技术约束与实现路径
- **前端基建**：Electron + 现代前端框架 (React/Vue 推荐) + TailwindCSS。
- **智能引擎**：云端大模型 API 驱动。需在应用内提供 API Key 配置入口，支持 DeepSeek/OpenAI 等。
- **数据获取**：API 驱动模式。通过调用第三方接口 (如新闻 API) 实现热点抓取，不写复杂爬虫。
- **Agent 机制**：Node.js 后端常驻。通过定时任务 (如 node-cron) 在后台拉取数据，更新本地数据库。
- **代码质量要求**：结构清晰，组件化拆分。考虑到未来开源，必须写关键逻辑注释，并生成简单 README.md。

## 3. 视觉与交互设计
- **整体布局**：左侧可折叠侧边栏导航 + 右侧主内容区。
- **视觉基调**：温暖护眼的手帐风。米白色/浅木色背景，圆润组件，柔和阴影，拒绝冷硬的科技风。
- **今日热点交互**：
  - 在板块内直接与 Agent 对话，输入想看的领域 (如"AI前沿")，Agent 解析后自动去网络获取并分板块展示。
  - 以信息流/卡片墙形式展示，点击卡片直接跳转至源网页。
- **今日待办交互**：
  - 根据制定的每日计划进行列表陈列。
  - 支持打勾操作，打勾后触发划除线动画，给予正向心理反馈。

## 4. 数据与内容规范
- **存储载体**：采用 lowdb (基于 JSON 的轻量数据库)，数据完全本地化。
- **关联性设计**：强关联。所有核心实体均以唯一 ID (UUID) 作为主键，实体间关联通过存储对应 ID 实现。
- **软删除机制**：所有核心实体表必须包含 `isDeleted` (Boolean) 和 `deletedAt` (Timestamp) 字段。常规查询默认过滤已删除数据。
- **基础实体示例**：
  - `todos`: { id, content, projectId, status, isDeleted, createdAt, completedAt }
  - `projects`: { id, name, status (active/paused/dropped/done), isDeleted, createdAt }
  - `notes`: { id, type (book/atomic), title, content, linkedNoteIds [], isDeleted, createdAt }

## 5. 板块规划清单 (全量 MVP 范围)
第一版 MVP 要求上述所有板块能够基本使用：
1. **今日总览**：聚合仪表盘，展示今日待办摘要、今日热点速览、昨日复盘精华等。
2. **计划**：包含 今日计划、本周计划、本月计划 子模块。
3. **复盘**：包含 今日复盘、本周复盘、本月复盘 子模块。
4. **项目**：看板视图或列表视图，分为 进行中、已完成、已暂停、已放弃。
5. **运动**：记录运动数据并展示运动趋势图表。
6. **知识库**：分为 阅读书籍、读书笔记、原子笔记 (支持双向链接)。
7. **今日热点**：Agent 主动获取并展示，支持点击跳转。
8. **灵感速记**：全局快捷唤起，快速记录碎片想法，自动归档至收件箱。
9. **设置**：API Key 配置、Agent 行为自定义、数据备份路径等。
