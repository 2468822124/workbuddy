## 1. 协作模式与闭环

沿用 WorkBuddy 三角色：

| 角色 | 职责 |
|---|---|
| **GLM（项目经理 / 审查）** | 在本文件夹内起草 `规格-子阶段N-*.md`、验收点、评审清单；**不写实现代码** |

**闭环选择**：本功能为多子阶段开发（非一次性 CR），且阶段 6 尚未全关闭（待用户实跑 E2E），故走**构建期闭环**：

## 2. 功能概览与定位

**计划与复盘体系**是 WorkBuddy「手帐 / 计划 / 晨间起胞器」灵魂的延续。它把 v0.3 §5.2 推迟的两块能力补齐：

- **计划**：模板驱动，写一份日/周计划，保存时自动解析 `- [ ]` 任务项 → 生成 `todos` → 流入「今日待办卡」，闭合「计划 → 执行」数据环。
- **复盘**：模板驱动，写日/周复盘；可由 LLM 拉取昨日完成情况自动汇总草稿；最新复盘摘要展示在「昨日复盘卡」，闭合「执行 → 复盘 → 调整」环。

**定位**：**离线优先 + LLM 增强**。无 LLM 时全流程可用（手动填模板）；配 LLM 后获得「引导式提问」与「复盘自动汇总草稿」两项增强，且优雅降级。

## 3. 范围

**含**：
- `templates` 基建：仓储 / IPC / 默认模板 seed（镜像用户 Obsidian SOP）/ 选择与编辑。
- `plans` 基建：仓储 / IPC / CRUD + 解析 `- [ ]` → `todos` + `plans↔todos` 关联（编辑幂等）。
- `reviews` 基建：仓储 / IPC / CRUD + 衔接「昨日复盘卡」。
- 适度 Markdown 编辑器组件（编辑 + 实时预览 + `- [ ]` 任务解析 + 基本工具栏）。
- 计划 / 复盘路由与侧边栏入口。
- LLM 增强（子阶段 4）：引导式提问、复盘自动汇总草稿，含降级。

**不含（推迟）**：
- 知识库 / 双向链接（独立功能项目）。
- 模板的高级可视化编辑器（本期仅 Markdown 源码编辑）。
- 周 / 月复盘的跨期统计图表。
- 计划与外部日历的同步。
- 移动端。

## 4. 关键技术决策

1. **复用现有表，新增一条治理迁移**：`plans` / `templates` / `reviews` 已在 `0001_init.ts` 建表，但缺软删除 / 时间戳治理字段 → 新增 **`0003_plan_review_governance`** 迁移补齐（详见 §5）。**不修改已发布的 `0001`**。
2. **计划生成的 todos**：`projectId = NULL`（`todos.projectId` 可空，`ON DELETE SET NULL` 已证），按 `planDate` 聚合到「今日待办卡」。与项目管理详情页创建的 todos 形成**双入口**，统一表、统一卡。
3. **解析幂等**：再次保存计划时，按行内容对未勾 `- [ ]` 做**增量 / 去重**——新增项建 todo，已存在项保留（尤其保留已勾完成项与 `completedAt`），不重复建、不误删。
4. **LLM 定位**：引导式提问 / 复盘汇总均为**用户主动触发**（非后台自主），故不受 §9「后台单次 ≤1000 tokens」红线约束，但需加护栏（上下文裁剪、单次请求上限、失败即停不重试）。
5. **Markdown 编辑器**：选轻量库（如 `marked` + `DOMPurify` 渲染、或 `@milkdown/crepe` 等可考虑由 DeepSeek 在子阶段 1 选型），**不做 WYSIWYG**；`- [ ]` 渲染为可勾选框。为未来知识库编辑器留可复用组件，但不提前实现知识库特性（YAGNI）。
6. **IPC**：沿用现有强类型通道 + 统一错误信封（项目计划 §4.5）。
7. **导入导出**：三表已在 `src/main/services/data.ts` 的 `BUSINESS_TABLES` 内，新增列后导入导出仍按行往返，无需改导入导出逻辑（DeepSeek 在子阶段 1 核对）。

### 5.3 新增迁移 `0003_plan_review_governance`（DDL 草案，DeepSeek 按命名规则定文件名/格式）

ALTER TABLE plans     ADD COLUMN updatedAt TEXT NOT NULL DEFAULT '';

ALTER TABLE templates ADD COLUMN isDeleted INTEGER NOT NULL DEFAULT 0;
ALTER TABLE templates ADD COLUMN deletedAt TEXT;
ALTER TABLE templates ADD COLUMN createdAt TEXT NOT NULL DEFAULT '';
ALTER TABLE templates ADD COLUMN updatedAt TEXT NOT NULL DEFAULT 0;   -- isDefault 已存在

ALTER TABLE reviews   ADD COLUMN createdAt TEXT NOT NULL DEFAULT '';
ALTER TABLE reviews   ADD COLUMN updatedAt TEXT NOT NULL DEFAULT '';
ALTER TABLE reviews   ADD COLUMN isDeleted INTEGER NOT NULL DEFAULT 0;
ALTER TABLE reviews   ADD COLUMN deletedAt TEXT;

-- 计划按日期查询常用，补索引
CREATE INDEX IF NOT EXISTS idx_plans_date   ON plans(date)   WHERE isDeleted=0;
CREATE INDEX IF NOT EXISTS idx_reviews_date ON reviews(date) WHERE isDeleted=0;

- **Day-1 启用**：是（子阶段 1 即执行，先于任何业务逻辑）。
- **迁移系统**：沿用现有 migration 版本化机制（项目计划 §4.1）；**版本号用 0003**（`0002` 已被 `0002_news_items` 占用）；`0003` 在应用启动时自动跑，存量 0.1.0 库平滑升级。

## 6. 核心设计

### 6.1 模板驱动流

```
进入「计划/复盘」→ 选日期 + 选 type → 拉 templates[type]（默认取 isDefault）
→ 渲染 Markdown 模板到编辑器 → [有 LLM] 占位符 {{...}} 逐项引导式提问（内联面板）
                                       [无 LLM] 用户直接手动填写
→ 保存
```

### 6.2 计划解析 → todos（幂等）

```
保存计划时：
  1. 扫描 content，提取所有「未勾选任务行」(正则: /^\s*[-*]\s+\[\s\]\s+(.+)$/ )
  2. 取该 plan 已有 generatedTodoIds → 查这些 todo 的 content 集合 S
  3. 对新提取的每行：
       - 若 content ∈ S → 复用已有 todo（不重建，保留 status/completedAt）
       - 否则 → 新建 todo(content, planDate=plan.date, projectId=NULL, status='todo')
  4. 更新 plan.generatedTodoIds = 并集；回填 plan.updatedAt
  5. 解析异常（格式不合法）→ 放弃解析、保原文、底部提示（§12），不崩溃
```

- 已勾选 `- [x]` 行**不**纳入新建，但若对应 todo 已存在则保留其完成态。
- 删除计划文档中某行：本期**不**自动软删对应 todo（避免误删），仅在文档底部提示「检测到 N 条任务已移除文档，对应待办仍保留，可在项目管理清理」。此为安全默认，可在子阶段规格细化。

### 6.3 复盘 + 昨日复盘卡衔接

- 复盘 CRUD：同计划，无解析动作（复盘不生成 todos）。
- **昨日复盘卡**（今日总览）：替换现有 EmptyState → 读取 `reviews` 中 `date = 昨天` 且 `type = daily_review` 的最新一条，渲染摘要（首段或前 N 字）+ 「写复盘」入口（跳复盘页并预填日期）。

### 6.4 LLM 增强（子阶段 4，降级容错）

- **引导式提问**：用户点「AI 引导」→ 主进程取模板占位符 + 已填上下文 → 调 OpenAI 兼容 Chat → 逐项提问/建议 → 用户采纳后回填编辑器。**内联面板，禁模态弹窗**（§9）。
- **复盘自动汇总草稿**：打开日复盘点「AI 汇总」→ 主进程拉昨日 `completed` todos + 相关项目进展 → 调 LLM 生成草稿 → 回填编辑器供用户改。
- **降级**：未配 LLM → 隐藏/禁用这两入口并提示「前往设置配置 AI」；LLM 调用失败 → 模块内红色状态条 + 本地日志 + 停止重试（§12）。
- **护栏**：单次请求裁剪上下文（如 todos 限 50 条、内容截断），设单次 token 上限，防资费异常。

## 7. IPC 契约（新增强类型通道）

> 沿用现有 `ipcMain`/`preload` 强类型桥 + 统一错误信封。DeepSeek 在 `shared` 定义类型，通道名最终以 `命名规则.md` 为准。

| 通道 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `template:list` | `{ type?: TemplateType }` | `Template[]` | 按 type 过滤，排除软删 |
| `template:get` | `{ id }` | `Template \| null` | |
| `template:upsert` | `Template` | `Template` | 新增/编辑（含默认模板管理） |
| `template:delete` | `{ id }` | `{ ok }` | 软删；默认模板禁删 |
| `plan:create` | `{ date, type, templateId?, content }` | `Plan` | 解析并生成 todos（§6.2） |
| `plan:update` | `{ id, content, ... }` | `Plan` | 幂等再解析 |
| `plan:get` | `{ id }` | `Plan \| null` | |
| `plan:list` | `{ type?, from?, to? }` | `Plan[]` | 按日期范围 |
| `plan:guideQuestion` | `{ templateId, filled, placeholder }` | `{ question/suggestion }` | LLM；无 LLM 返回降级标记 |
| `review:create` | `{ date, type, content, linkedProjectIds? }` | `Review` | |
| `review:update` | `{ id, content, ... }` | `Review` | |
| `review:get/list` | 同 plan | | |
| `review:summarizeDraft` | `{ date }` | `{ draft }` | LLM；拉昨日完成情况生成草稿；无 LLM 降级 |

所有返回走统一信封 `{ success, data?, error? }`；LLM 通道在未配 LLM 时返回 `{ success:false, error:'LLM_NOT_CONFIGURED' }` 由前端降级。

## 12. 禁止边界 & 错误降级（承袭项目计划 §7-B/§7-C，按本功能具化）

**禁止边界**：
- 日志严禁输出计划 / 复盘正文或 API Key 明文。
- 业务数据严禁上传非用户指定云端。
- 删除一律软删除，必须前端用户主动触发。
- 引导式提问 / 复盘汇总**禁模态弹窗**、禁自动播放音视频。
- 后台自主 LLM 单次 ≤1000 tokens（本功能 LLM 均为用户主动触发，不受此红线，但仍加护栏防资费异常）。

**错误降级**：
- **LLM 失败**：停止重试防雪崩 + 本地日志 + 模块内红色状态条；引导/汇总入口在未配 LLM 时禁用并提示去设置。
- **Markdown 解析异常**：放弃解析、保留原文、文档底部提示「部分内容无法识别为任务，已保留原文」。
- **DB 锁定/损坏**：沿用全局安全模式（只读 + Toast）。
