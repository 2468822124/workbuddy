## 1. 单元目标

把「计划」+「复盘」两个顶层板块合并为统一「**规划**」，按 **日 / 周 / 月** 三级展开，每级同页完成「**回顾本期 + 规划下期**」一线流转：

- **日规划**（晚间）：回顾今日（轻量：完成率 + 已完成 + 遗留顺延）+ 规划明日（编辑器 + 日任务 → 每日待办 + 从本周周任务点选下沉）。
- **周统筹**（周末）：**AI 结构化周复盘**为主（重大事件 / 亮点 / 不足·现象-原因-改进 / 上周风险复查表 / 风险评估 / 下周建议，按下级日级数据生成，可编辑+重新生成）+ 规划下周为辅（精简方向 + 周任务 + 从本月月任务点选下沉）。
- **月指导**（月末）：**AI 结构化月复盘**为主（整月宏观完成率&任务数图 + 每周完成率&任务数图 + 风险评估 + 经验教训 + 下月建议，按下级周级复盘聚合生成）+ 规划下月为辅（月任务，级联源头）。

一句话演示：**周末进「周统筹」→ AI 按本周每天完成情况生成结构化复盘（含目标对照/亮点/不足/风险）→ 看清本周做到了没 → 顺势规划下周，把月任务点选下沉为周任务（月任务同步划掉）。**

今日总览留「执行」（待办 + 热点），计划/复盘移交规划；周日/月末自动在每日待办生成「做周统筹 / 做月指导」提醒。

**含**：
1. **IA 重构**：侧栏「计划」+「复盘」→ 一个「规划」（可展开：日规划/周统筹/月指导）；路由 `/plan` `/review` → `/planning/:level`（`daily|weekly|monthly`）。

3. **期键计算**（`@shared/period.ts` 新增纯函数）：ISO 周一始周日终；`getWeekStart/getWeekRange/isoWeekOf`、`getMonthStart/getMonthRange`、`nextPeriodStart`、标签 `第 N 周 · MM/DD–MM/DD` / `YYYY 年 M 月`。
4. **数据语义扩展**：`TemplateType` + `Plan.type`/`Review.type` 加 `monthly_plan`/`monthly_review`；plans/reviews 的 `date` 作「期起始」（日=当天、周=周一、月=1 号）；`planRepo`/`reviewRepo` 加 type+期 起始查询与范围聚合只读方法。**无新表 / 无迁移**（方案 A，复用现有索引；见 §6）。
5. **任务级联 + 点选回写**：周/月 plan 的 `- [ ]` 任务不生成 todos；下级页面侧栏展示上级任务供「选取」→ 插入下级任务 + **同步把上级任务标记为已下沉（`- [ ]`→`- [x]`，渲染划掉、不再可选）**。
6. **AI 结构化复盘生成**：`summarizeWeeklyReview(periodStart)` / `summarizeMonthlyReview(periodStart)`（`services/llm.ts` 新增，复用 `requestChat`），按下级数据（周←本周日级完成+日复盘；月←本月周级复盘+完成统计）+ 本期目标 + 上期风险，生成 Markdown 复盘文档；可编辑（MarkdownEditor）+ 「重新生成」。
7. **确定性数据可视化**：完成率环（周/月）+ 月级「整月宏观完成率&任务数」+「每周完成率&任务数」图表（从 todos 聚合，非 AI）。
8. **自动提醒任务**：app 启动时检查今日——周日→生成「做周统筹」待办、月末→生成「做月指导」待办（幂等）；点击「前往」跳对应级。
9. **今日总览精简**：移除「今日计划」链接 + 「昨日复盘」卡（移交日规划）；保留待办执行 + 热点。

**不含（推迟）**：
- 复盘的多轮追问/对话式生成（本子阶段为**单次生成整份 Markdown 草稿**，用户编辑/重新生成）。
- 流式输出（沿用 `stream:false`）。
- 「点选回写」的反向同步（下级删任务→上级自动取消划掉）：**不做**（YAGNI）；用户需恢复可手动编辑上级 plan 的 `- [x]`→`- [ ]`。
- 自动提醒任务的点击「前往」之外的高级调度（如自定义提醒时间/开关）：仅固定「周日/月末」规则。
- 知识库/运动模块（仍「敬请期待」，不动）。
- 历史已存日计划/日复盘数据的强制重映射：存量按原 `daily_plan`/`daily_review` 类型自然归入「日规划」回顾；周/月为新内容，不回填历史。

### 5.1 信息架构与路由

  - `/planning/daily` 日规划（icon `Calendar`）
  - `/planning/weekly` 周统筹（icon `RefreshCw` 或 `Calendar`，自选已注册图标）
  - `/planning/monthly` 月指导（icon `Calendar`）
  - 父项点击展开/收起（本地 `ref`）；当前子项高亮（`isActive` 改为支持前缀匹配 `/planning`）。子项图标必须已在 `AppIcon` 注册（参照子阶段1 F1 教训：模板用到的 name ⊆ 已注册集）。
- **路由**（`router/index.ts`）：新增 `/planning/:level` → `PlanningView.vue`（`props: true`，level ∈ daily|weekly|monthly，非法值重定向 `/planning/daily`）。**旧路由 `/plan` → `/planning/daily`、`/review` → `/planning/daily`（重定向，保兼容**，因 ReviewView 的回顾今日已并入日规划；周/月复盘入口在侧栏子项）。`?date=` query 仍支持（预填期）。
- **今日总览**（`TodayView.vue`）：移除 `今日计划` 链接（`TodayView.vue:87`）与 `昨日复盘` 卡（`:172-196`）；待办卡内若一条 todo 命中周期提醒模式（见 5.7），渲染「前往 →」按钮 `router.push('/planning/weekly'|'/planning/monthly')`。

### 5.2 期键计算（`@shared/period.ts`，纯函数，vitest 必覆盖）

```ts
export type PlanningLevel = 'daily' | 'weekly' | 'monthly'

// 周一始周日终（用户锁定）
export function getWeekStart(date: string): string       // 输入 'YYYY-MM-DD' → 本周周一 'YYYY-MM-DD'
export function getWeekRange(date: string): [string, string]  // [周一, 周日]
export function isoWeekOf(date: string): number          // ISO 周数（周一始）
export function getMonthStart(date: string): string      // 本月 1 号
export function getMonthRange(date: string): [string, string]  // [1号, 月末日]
export function periodStartFor(level: PlanningLevel, date: string): string  // daily→date; weekly→getWeekStart; monthly→getMonthStart
export function nextPeriodStart(level: PlanningLevel, start: string): string  // 下一期起始（daily +1天；weekly +7天；monthly 进次月1号）
export function periodLabel(level: PlanningLevel, start: string): string  // weekly→`第 N 周 · MM/DD–MM/DD`；monthly→`YYYY 年 M 月`；daily→`YYYY-MM-DD`
```

> 实现：用纯算术（**不依赖 `new Date()` 的本地时区漂移**；`Date` 构造用 UTC 或显式 `Date.UTC` + `getUTC*`，避免子阶段3 LOW-1 的 UTC/local 议题复现）。`isoWeekOf` 按周一为周首的 ISO 算法（与「周一开始」一致）。vitest：跨年周、月末、闰年、`2026-08-07`(周五)→本周一 `2026-08-03`、ISO 周数、下期计算等 ≥10 例。

### 5.3 PlanningView（三级共用）

- `props: { level: PlanningLevel }`；`date` 初值：`route.query.date` 或今天。
- 计算本期起始 `curStart = periodStartFor(level, date)`、下期起始 `nextStart = nextPeriodStart(level, curStart)`。
- 布局：页头（`periodLabel` + 上/下期切换箭头改 `date`）+ **ReviewPanel**（复盘本期，引用 `curStart`）+ **PlanPanel**（规划下期，引用 `nextStart`；日级时 PlanPanel 为主、ReviewPanel 轻量；周/月反之，由组件内 `level` 分支控制视觉权重，用 `role-tag` 标注「复盘·主干 / 规划·次要」）。
- 期切换：`‹ ›` 把 `date` 改为上/下一期起始（daily ∓1 天；weekly ∓7 天；monthly ∓1 月）。

### 5.4 任务级联 + 点选回写（核心，含用户补充规则）

**任务来源**：周/月 plan 的 `- [ ]` 任务 = 该 plan.content 里未勾选行（`planParser.parseTasks`）；**不生成 todos**（IPC `runSync` 按 type 门控：仅 `daily_plan` 调 `syncPlanTodos`，`weekly_plan`/`monthly_plan` 跳过）。

**`parseTasksWithState(content)`**（`planParser.ts` 新增，原 `parseTasks` 保留不动）：返回 `{ text: string; consumed: boolean }[]`——
- `- [ ] text` → `{ text, consumed: false }`（可选）
- `- [x] text` → `{ text, consumed: true }`（已下沉，划掉）

**点选动作**（下级 PlanPanel 的 CascadeRail）：
1. 用户在「日规划-规划明日」的 CascadeRail 点某条本周周任务「选取」 →
   - **插入下级**：把 `taskText` 追加到下级（明日 daily_plan）`editContent` 的任务清单区（renderer 本地编辑，随后走既有 `plan:create/update` 保存）。
   - **回写上级（用户补充规则）**：调 `plan:markTaskConsumed({ planId: <本周 weekly_plan 的 id>, taskText })` → 主进程把该 weekly_plan.content 里**首条匹配** `- [ ] {taskText}` 改写为 `- [x] {taskText}`，`planRepo.update` 保存，返回更新后的 plan。
2. CascadeRail 重新拉取上级任务（`plan:listTasksByPeriod`）→ 被 mark 的任务现 `{consumed:true}` → 渲染**划掉 + 无「选取」按钮**；未消费的仍可选。
3. 周统筹-规划下周 同理：点本月月任务「选取」→ 插入下周 weekly_plan + `plan:markTaskConsumed(monthly_plan_id, taskText)`。

**幂等与边界**：
- `markTaskConsumed`：上级 content 里无 `- [ ] {taskText}`（已 `[x]` 或不存在）→ no-op，返回当前 plan（不报错）。
- 任务文本匹配：**精确字符串**（去首尾空白）；若同文本多行，标记首条。用户后续手动编辑上级 plan 可能解除标记（可再选）——可接受。
- 下级插入去重：若下级 `editContent` 已含 `- [ ] {taskText}`，不重复插入（renderer 判定）。
- **不做反向同步**（下级删任务不自动恢复上级 `- [ ]`）；用户手动改上级。已知限制，写入 §11。

### 5.5 AI 结构化复盘生成（`services/llm.ts` 新增）

复用子阶段 4 `requestChat`/`ChatError`/`parseJsonObject` 范式；**输出为 Markdown 文档**（存入 review.content，MarkdownEditor 可编辑渲染）。

#### 5.5.1 `summarizeWeeklyReview(periodStart: string): Promise<{ content: string; latencyMs: number }>`

periodStart = 本周周一。上下文构造 `buildWeeklyContext`：
- **本期目标**：本期 weekly_plan（`planRepo.getByPeriod('weekly_plan', periodStart)`）的 content（重点/任务区）——若本期无 plan，目标留空。
- **本周完成**：`todoRepo.findCompletedInRange(weekStart, weekEnd)` 取 content（截断 `LLM_REVIEW_TODO_CHARS`，上限 `LLM_REVIEW_TODO_LIMIT`）。
- **本周日级复盘**（下级）：`reviewRepo.findAll({ from: weekStart, to: weekEnd, type: 'daily_review' })` 取每条 content 前 `LLM_REVIEW_SUB_CHARS`，上限 `LLM_REVIEW_SUB_LIMIT` 条。
- **上期风险**：上周 weekly_review（`reviewRepo.getByPeriod('weekly_review', 上周周一)`）的 content（若有，整体截断传入）。
- **进行中项目**：`projectRepo.findActive().slice(0, LLM_PROJECT_LIMIT)` name/status/openTasks（不暴露 description）。

#### 5.5.3 失败降级（承袭子阶段4）

`requestChat` 抛 `ChatError`（401/403→LLM_AUTH、429→LLM_RATE_LIMIT、5xx→LLM_UNAVAILABLE、网络→LLM_NETWORK、超时→LLM_TIMEOUT、未配→LLM_NOT_CONFIGURED）→ IPC 映射 `err(code,msg)` → 组合式置 `error` → ReviewPanel 红色状态条 + 「重试」；**单次不重试**。模型输出非法（空/超长非 Markdown）→ `stripFence` 兜底 + `content.slice(0, 6000)`，不崩。

### 5.6 确定性数据可视化（非 AI）

- **CompletionRing**：入参 `{ done: number; total: number }`，渲染 conic-gradient 环 + `done/total` + `完成率 N%`。
- 完成率数据源：周/月级 `total = todoRepo.findAllInRange(start, end).length`（`planDate` 在期内、`isDeleted=0`），`done = todoRepo.findCompletedInRange(start, end).length`（`status='done' AND completedAt` 在期内）。日级沿用 `useToday`/既有今日统计。
- **MonthlyCharts**（月级 ReviewPanel）：
  - **整月宏观**：CompletionRing(月) + 完成数/总数 + 完成/未完成分割条（CSS）。
  - **每周**：把月内按 `getWeekStart` 切成 N 周（与月边界相交的周计入），每周末/月末取整周或截断到月；每行一周，横向条：**条长 = 该周任务总数（相对月内最大周）**、**填充 = 该周完成率**，右固定列 `完成率%` + `done/total`，底部 caption「柱长=任务总数·填充=完成率」（**照搬用户已确认的样张设计**）。
  - 数据：对每周调用 `findAllInRange`/`findCompletedInRange` 聚合（前端按 `getWeekStart(todo.planDate)` 分组，或主进程一次范围查询后前端分组——DeepSeek 选，前者简单）。
- **目标对照表（GoalScorecard）**：渲染 AI Markdown 里的 `## ◎ 本期目标达成对照` 表格（MarkdownEditor 预览渲染 `<table>`），或从 review.content 解析该 section。**默认随 AI Markdown 一起渲染**（不单算）——简化：ReviewPanel 上半 = CompletionRing（确定性），下半 = AI Markdown 文档（含目标对照表 + 各 section，MarkdownEditor 渲染）。

> 即：复盘卡 = 顶部 CompletionRing（确定性）+ AI Markdown 文档（目标对照/重大事件/亮点/.../建议，可编辑+重新生成）。月级在 CompletionRing 与文档之间插 MonthlyCharts。这样避免「结构化 JSON 分区编辑」的复杂度，编辑即编辑 Markdown 原文。

## 10. 禁止边界 & 错误降级（承袭项目计划 §7 三表，按本子阶段具化）

**禁止边界（§7-B）**：
- **日志**：apiKey 永不入（`logger.redact` 兜底 + 调用方不传）；**禁记** todo content / 复盘 Markdown / 下级复盘摘要 / 目标明文；错误仅记 `ChatError.code`，成功仅记 latency/长度/计数。
- **私有数据外发**：任务 content（截断）+ 项目 name/status/counts + 下级复盘摘要 发往**用户自配** `llmBaseUrl`（§9「用户指定端点」豁免 + 用户主动触发「生成」）；**严禁**外发 projects.description / notes / inboxes；按钮旁内联透明提示（非模态）。**不新增设置开关**（透明提示替代）。
- **token 红线**：本子阶段全前台用户触发，红线 N/A；仍设 `LLM_WEEK/MONTH_REVIEW_MAX_TOKENS:1600` + 上下文/下级/截断三重护栏。
- **软删除**：本子阶段不改数据删除语义（markTaskConsumed 改 content 文本不软删；提醒 todo 可被用户软删，标准 todoRepo.softDelete）。
- **无模态弹窗**：错误用模块内红色状态条；「去设置」路由跳转；透明提示内联 span。
- **XSS**：复盘 Markdown 经 MarkdownEditor(DOMPurify)；CascadeRail 任务文本、periodLabel 全 `{{}}` 插值；禁自写 v-html。
- **无新表/无迁移**（grep `migrations/` 无新增；schemaVersion 仍 3）。
- **无硬编码 hex / 新图标注册核** / 静态 import。

**错误降级（§7-C）**：
- **LLM 失败**（401/403、429、5xx、网络、超时）：单次不重试 + 本地日志（脱敏）+ 模块内红色状态条 + 可读 code 映射 + 「重试」。
- **模型输出异常**（空/非 Markdown/误包代码块）：`stripFence` 剥围栏 + `content.slice(0,6000)`；不崩；缺 section 提示重试。
- **无数据**（本期无完成任务/无下级复盘）：仍调 AI 但上下文标「（无）」，AI 应产出「（本期无完成任务记录）」式文档；不强报错（与子阶段4 U6 短路精神一致——但周/月**仍允许调用**，因为目标对照/风险即使无完成数据也有价值；由 AI system prompt 处理空态）。
- **未配 LLM**：入口 disabled + 非阻塞「去设置」，不发包。
- **期键算错**（如跨年周）：vitest 覆盖；运行时若 date 非法，`periodStartFor` 兜底回当天。
- **markTaskConsumed 并发**（用户同时编辑上级 plan）：按 `createdAt DESC` 最新 plan 操作；匹配失败 no-op，不报错。
