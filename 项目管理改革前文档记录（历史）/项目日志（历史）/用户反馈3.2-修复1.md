## 3. 偏差/取舍记录
| 偏差点 | 说明 | 原因 |
|---|---|---|
| migration 0004 | 触「无 migration」规格边界（此前多轮均「3 不变」） | F3.2-2 定稿 Tier2 明确要求 sourcePlanId 数据基础，无 schema 改无法实现；**用户已定稿此方案** |
| done orphan 保留在 generatedTodoIds | 方案B 语义：复用池 `!isDeleted`，done 未软删故命中 | 定稿 §3.1 回归③「复用保留完成态」的实现前提 |
| keptDoneCount 每轮重复提示 | 每次保存都重算计数（done orphan 未删故持续计入），用户反复保存会重复看到提示 | 保留为历史是方案B 定稿语义；提示为信息性，非阻断 |
| node:sqlite 测试 mock 策略 | better-sqlite3 本机 ABI（Electron 130）与 node CLI（127）不兼容 → vi.mock connection 用 node:sqlite DatabaseSync + 兼容包装（pragma 补 PRAGMA 前缀 / transaction 返回包装函数 / named 参数宽松过滤 / rest 参数 spread） | 测试必须跑真实 repo SQL（in-memory），此为最小 mock 面 |
| period.spec.ts L92 断言修复 | 既存 flaky（断言用 UTC toISOString，实现用本地日期，本地 00:00–08:00 跨午夜段不一致）；改断言用本地日期计算，与 period.ts todayStr() 对齐 | 非本次引入的缺陷；flaky 测试在跑新测试时暴露（2026-08-09 凌晨复现），一并修正避免回归误报 |
| isDeleted 断言用 toBe(1)/toBe(0) | DB 存储 1/0 数字，repo 层 SELECT 不归一化 | 与既有 better-sqlite3 行为一致，测试如实断言 |
| 存量 27 todo sourcePlanId 全 null | 不迁移历史数据（不猜测出处），首次同步后新建 todo 才有 sourcePlanId；存量靠 labelTodoSource 降级规则（手动/顺延）兜底 | F3.2-2 定稿「不迁移历史」原则 |
| W33 buggy `[x]` 值不自动清理 | DB 用户数据只读 | 既有约束，未触碰 |
