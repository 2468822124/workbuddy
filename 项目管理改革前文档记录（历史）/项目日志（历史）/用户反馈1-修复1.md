## 元信息
- **日期**：2026-08-07
- **修复人**：DeepSeek（04 prompt）
- **对应反馈**：用户反馈1 — 安装后双击图标无法启动
- **根因确认**：`settingsRepo.seedDefaults()` 内动态 `require('./defaultSettings')` 在 electron-vite SSR bundle 中不解析 → `Cannot find module` → `createWindow()` 从未执行

## 修改文件

### 1. 主修复：`src/main/db/repositories/settingsRepo.ts`（§5 主修复）
- **改了什么**：删除 `seedDefaults()` 内的 `const { getDefaultSettings } = require('./defaultSettings')`（动态 require），文件顶部加 `import { getDefaultSettings } from './defaultSettings'`（静态 import）
- **为什么**：静态 import 被 electron-vite 正确打包进 bundle；动态 require 相对路径在 bundle 内运行时找不到独立文件
- **验收**：编译输出 `out/main/index.js` 中 `getDefaultSettings` 函数已在行263内联定义，`seedDefaults()` 直接调用，无 require 调用

### 2. 加固1：`src/main/index.ts`（§5 附带加固1）
- **改了什么**：`app.whenReady` 内的启动序列（initDb→migrate→seedDefaults→registerAllIpc）包 try/catch，`createWindow()` 独立 try/catch 确保始终执行
- **为什么**：任一启动步骤抛错不再导致窗口静默不创建

### 3. 加固2：`src/main/window.ts`（§5 附带加固2）
- **改了什么**：加 `import { logger }`，加 `webContents.on('did-fail-load', ...)` 处理——记录错误详情 + 兜底 `show()` 窗口
- **为什么**：加载失败时不再黑盒 `show:false`，至少显示窗口暴露问题

### 4. 加固3：grep 排查其他动态 require（§5 附带加固3）
- **结果**：仅 `settingsRepo.ts` 一处 `require('./defaultSettings')`，无其他同类问题
