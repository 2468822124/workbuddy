## 逐项详情

### 1. F3-1 — 日规划页串档加载周模板/周复盘（🔴 必修）

- **根因**（GLM §4 诊断，代码逐行核实一致）：`PlanningView.vue:26-28` setup 顶层一次性求值冻结 `plan`/`planType`/`reviewType`；vue-router 对同组件不同路由参数（`/planning/daily|weekly|monthly`）默认**复用组件实例、不重跑 setup** → 切换 level 后 `load()` 仍按首次 level 的 planType/reviewType 查数据（`api.plans.getByPeriod` / `api.reviews.byDate` / `api.templates.list`），CascadeRail 上级 level 也错。
- **改动**：`AppLayout.vue` `<router-view />` → `<router-view :key="route.path" />`（`<script setup>` 引入 `useRoute`）。level 切换 → path 变 → 组件重建 → setup 重跑 → 派生量按新 level 求值。
- **关键取舍（按 GLM §5 明示）**：用 `route.path` 而非 `route.fullPath`——同 level 内翻期走 `router.replace({ path, query: { date } })`，date 在 query；path 不变 → 不重建 → 不丢草稿、不重复 mount（既有 `watch(curStart)` + `load()` 处理翻期）。若误用 fullPath，翻期即重建，是回归。
- **影响面核验**：其余路由（/today、/projects/:id、/settings）path 各异，key=path 下切换本就换组件，无副作用。备选方案（planType 改 computed + usePlanning 响应式化）改动面大，按 §5 不采用。
- **回归说明（写入 §5 验证点第 1 条）**：同会话 周统筹→日规划→月指导→日规划 每级显示本级正确模板 + 本级复盘 + 本级 CascadeRail 标题（见下方运行时验证）。

### 2. F3-2 — 日期切换增加日历选日期（🔵 同批）

- **改动**（PlanningView.vue，按 §5 推荐实现，三级通用）：
  - 模板：period-nav 内 `‹ ›` 后加日历按钮（`AppIcon name="Calendar"`，已注册）→ 点击调 `pickDate()` → `dateInput.showPicker()`（原生 Chromium 日期选择器，Electron 支持，无新增依赖、无模态，符合「禁阻断式模态」边界）。
  - 隐藏 `<input type="date">`：`ref="dateInput"`、`:value="curStart"`（选择器打开即定位当前期）、`@change="onPickDate"`。CSS 用视觉隐藏（opacity 0 + 1px 占位 + pointer-events:none，**不用 display:none**——Chromium `showPicker()` 要求元素已渲染）。
  - 逻辑：`onPickDate` 取 `input.value` → `curStart.value = periodStartFor(level.value, v)`——periodStartFor 自动归一化（日选当天、周选所在周周一、月选所在月 1 号），三级通用；赋值触发既有 `watch(curStart)` → `router.replace` 带 date + `load()`。
  - 样式全用 token（`--border`/`--bg-surface`/`--text-muted`/`--accent-ring`/`--accent`），无硬编码 hex（§5 要求）。
  - 箭头 `±1` 与「回到今天」保持原样。

修前对照（用户实测现象，反馈 §3 截图）：先开周统筹再开日规划 → 日规划显示「周计划·{{week}} / 本周重点{{focus}}…」+ 周复盘 + CascadeRail 空。修复后 DOM 实测日规划 = 日计划模板 + 本周周任务（含播种的周任务A/B）。
