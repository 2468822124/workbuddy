# 审查日志（GLM 维护）

> **维护方**：GLM（审查人员）。DeepSeek **不得**修改本目录。

## 用途
记录 GLM 对每个阶段/批次的审查与复审。每次审查产出一份记录，是阶段「通过/需修复/驳回」的唯一凭据。

## 命名
- 阶段首次审查：`阶段{N}.md`
- 阶段复审：追加在同一文件的「复审」小节；如复审核数多，新建 `阶段{N}-复审{M}.md`
- 维护期 CR 审查：`CR-{NNN}.md`（CR 审查基准 = `变更请求/CR-NNN` §5）
- SSOT/治理修复指令：`SSOT-修复指令-{YYYY-MM-DD}.md`（GLM 跨域下发给 DeepSeek 用 04 执行）
- 模板：`模板/审查日志模板.md`
- 完整命名/位置约定见 `项目规范/文档治理总纲.md §5`

## 结论三态
✅ 通过（构建期→可进下一阶段；维护期→执行关闭+版本+CHANGELOG）· 🟡 需修复（交 DeepSeek 用 04/08 prompt）· 🔴 驳回
