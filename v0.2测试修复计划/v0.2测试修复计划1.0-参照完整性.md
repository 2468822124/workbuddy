## 1. 单元目标

在 L2 半规范化模型上，根治计划与复盘体系「参照完整性」4 缺口（均为实测真问题，详见决策来源文档 §2）：

- **① 反向不同步** → 跨级删除分流（删上级 → 下游 open 消失 / done 标"来源失效"）。
- **② 文本匹配脆弱** → 稳定任务标识（tid），级联匹配键 text→tid，改名不破坏关联。
- **③ 出处链断裂** → `parentTaskRef` + 逐级溯源 UI（每任务标直接上级、可点击跳转、逐级到源头）。
- **④ 删除不传播** → 同①的跨级分流机制（周/月任务删除 → 下游 todo 按 open/done 分流）。

并为已验证的 4 个未来功能（交接流转 / AI 多轮问答 / AI 低完成率识别 / 项目任务池→今日+计划）预留扩展点，不在本期实现。

## 3. 核心设计

### 3.1 数据模型增量

**新增 `tasks` 表**（轻量，`planId` 归属；`plans.content` 仍为 Markdown 真相源，本表为其任务的"带身份索引 + 级联父子链"）：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `tid` | TEXT | PK | 任务稳定标识（随机 hex，如 `7f3a2b`；惰性分配，见 §3.2） |
| `planId` | TEXT | FK→plans.id | 所属计划（任务附属于计划文档，L2 语义） |
| `content` | TEXT | NOT NULL | 任务文字（**已剥除 tid 注释的纯净文本**） |
| `parentTaskId` | TEXT | FK→tasks.tid, NULLABLE | **级联父任务**：daily 任务←weekly 任务←monthly 任务。NULL=未级联（手输/源头） |
| `consumed` | INTEGER | DEFAULT 0 | 是否已下沉到下级（对应 `- [x]`，级联 consumed 状态） |
| `sortOrder` | INTEGER | | 行序（content 中行位置） |
| `createdAt` / `updatedAt` | TEXT | | 治理时间戳（同 plans 范式） |

**`todos` 加列**：
- `parentTaskRef` TEXT NULLABLE：JSON `{ parentPlanId, parentTaskId }` —— 该 todo 的**直接级联祖先**（来自哪个上级任务）。null=未级联（日规划手输/项目任务/周期提醒，按 `labelTodoSource` 既有规则降级显示）。

> 关系链：`todo.parentTaskRef.parentTaskId` → `tasks.tid`（weekly 任务）→ 该 task 的 `parentTaskId` → monthly task → … → NULL（源头）。出处链沿此遍历。

### 3.2 稳定标识策略（内联隐形 ID）— ✅ 关键评审点（已确认 2026-08-10）

**提案（GLM）**：任务行内联隐形 tid，Markdown HTML 注释形式：
```
- [ ] 写周报 <!-- tid:7f3a2b -->
```

**为什么必须内联（两条硬约束，无替代）**：
1. **扛改名（根治②）**：身份必须随任务行迁移。纯 tasks 表 + 位置/diff 匹配，改名被识别为"旧行消失+新行出现" → 关联断裂，②不成立。内联 tid 让改名只改文字、tid 不动 → 关联存活。
2. **出处链点击跳转定位**：点击"上级来源"需定位到上级 plan content 里的那条任务行；tid 锚点在 content 里才能精确定位（否则靠文字匹配，又是②）。

**惰性分配（降污染）**：tid 仅在任务"首次获得下游关联"时分配 —— 即被 `pickTask` 选入下级计划，或 `syncPlanTodos` 生成 todo 需写 `parentTaskRef` 时。纯日计划自用、不级联的任务**不贴 tid**（保持 content 干净）。

**污染控制**：
- 渲染态：`DOMPurify` 默认剥除 HTML 注释 → 预览不可见（需测确认；若被保留则配置 `FORBID_TAGS`/`keepContent: false` 剔除）。
- 编辑态：源码视图可见 `<!-- tid:xxx -->`（轻度污染，可接受）。
- `marked` 解析：HTML 注释不产生 DOM 节点（✅）。

**`planParser.parseTasks` 改造（tid 感知）**：
- 新正则（在现有 `- [ ]` 基础上可选捕获尾随 tid 注释）：
  `/^\s*[-*]\s+\[\s\]\s+(.+?)(?:\s*<!--\s*tid:([0-9a-f]+)\s*-->)?\s*$/`
- 返回 `{ text, tid? }[]`（`text` 已剥 tid 注释，存入 todo.content / tasks.content 时为纯净文本）。
- `parseTasksWithState`（子阶段5）同步改造：`- [x]` 行也带 tid。

**兜底**：若用户手删 tid 注释，下次该任务被级联引用时检测到无 tid → 重新分配（旧关联视为断裂，降级；UI 不崩）。

**备选（不采用，记录防反复）**：
- 位置/diff 启发匹配：content 零污染，但**扛不了改名**（②半根治），故否决。
- tasks 表为权威、content 为派生：动摇 Markdown-as-truth，滑向 L3，故否决。

> ✅ **已确认（用户 2026-08-10）**：采用"内联隐形 tid（惰性分配）"作为稳定标识方案，②真根治。

### 3.3 content ↔ tasks 双向 sync（保存时）

`planRepo.syncPlanTodos` 扩展（保存计划时，在现有 todo 同步前/后增加 tasks 同步）：
1. 解析 `plan.content` → `[{text, tid?, consumed}]`（含 `- [ ]`/`- [x]`）。
2. 取该 plan 已有 `tasks` 行（`WHERE planId=? AND isDeleted=0`）。
3. 对齐：
   - **有 tid 且仍在 content** → 更新 content/consumed/sortOrder（tid 不变，扛改名）。
   - **有 tid 但 content 已无该行** → 该 task 标记"被删"（触发 §3.6 跨级删除分流）。
   - **content 新行无 tid** → 若需级联（被下级引用过）则补分配 tid；否则不分配（惰性）。
4. 写回 `tasks` 表 + 回填 `plan.generatedTodoIds`（现有逻辑保留）。

**幂等**：再次保存按 tid 对齐，不重复建 task；已 consumed 的保留。

### 3.4 级联匹配键 text→tid

以下处全部由"文字精确匹配"改为"tid 匹配"：
- `usePlanning.pickTask`：选上级任务时，在下级 content 插入 `- [ ] {text} <!-- tid:{新tid} -->`，新 task 的 `parentTaskId` = 上级 task tid。
- `plan:markTaskConsumed` / `markTaskUnconsumed`（`plans.ipc.ts`）：按 tid 定位上级 plan content 行（`<!-- tid:xxx -->`），改 `[ ]↔[x]`；不再靠文字。
- `TODOS_TOGGLE` 双向同步（`todos.ipc.ts:32-81`）：todo 完成/取消 → 按其 `parentTaskRef.parentTaskId` 定位上级 task 行，改 `[ ]↔[x]`；不再靠文字匹配（根治②在该链路的复发）。

### 3.5 出处链（溯源 UI）

**`labelTodoSource` 升级**（`todoSource.ts`）：在现有 5 规则前**优先**判 `parentTaskRef`：
- `parentTaskRef` 非空且上级 task 存在 → 返回**直接上级**标签（如 `← 周任务·写周报`，可点击）。
- 否则走现有 5 规则（📌周期提醒 / 项目·名 / 日规划·天 / 顺延·天 / 手动·天）。

**UI（TodayView / PlanningView）**：
- 每条任务行末尾出处 tag：若有 `parentTaskRef` → 显示直接上级（任务文字 + 所属期），可点击。
- 点击 → 跳转该上级 plan（`router.push('/planning/{level}?date={parentPlan.date}')`）+ 定位任务行（按 `<!-- tid:{parentTaskId} -->` 在 content 查找，滚动+高亮）。
- 在上级 plan 内，该任务再显示**其**直接上级（若有）→ 逐级点击：todo → 周任务 → 月任务 → 源头（无上级）。

**性能**：`todos:withSource` IPC 扩展 —— batch 解析 `parentTaskRef` → 上级 task content（一次查询汇总 parentTaskId 集 → tasks 表查 content/planId → plans 表查 date/level），避免 renderer N 次 IPC。

### 3.6 删除语义扩展（跨级 open/done 分流）— 修①④

**机制**：`tasks` 同步（§3.3）检测到"上级 task 被删"（content 已无该 tid 行）时，触发对其**下游 todo** 的分流（沿用方案B 原则，扩展到跨级）：
1. 按 `parentTaskRef.parentTaskId = 被删 tid` 查下游 todo（`SELECT * FROM todos WHERE parentTaskRef LIKE '%"parentTaskId":"{tid}"%' AND isDeleted=0`，或建索引）。
2. 对每条下游 todo：
   - `status='todo'`（open）→ `todoRepo.softDelete`（今日总览消失）。
   - `status='done'` → 保留，`parentTaskRef` 标记失效（UI 显"来源已删"，置灰出处链）。
3. 计数 `removedOpenCount` / `invalidatedDoneCount`，PlanningView 提示。

**自洽性**：此为方案B open/done 分流原则向"跨级删除"方向的扩展，不违背方案B（done 仍留历史，仅标失效）。

**周/月删除传播（修④）**：周/月 plan 保存时，`runSync` 门控仍跳过 todo 生成（不变），但**新增** §3.3 的 tasks 同步 → 被删的周/月 task 触发 §3.6 下游分流 → 日 todo 按 open/done 处理。（此前④的根因是周/月根本不 sync；现在周/月做 tasks 同步即可触发跨级分流，无需生成 todo。）

### 3.7 项目任务选入计划（未来功能地基，本期打好）

虽 UI 另行，但本期在 `syncPlanTodos` 内**建好复用机制**：当日计划任务行对应的 todo，若存在已链接的项目 todo（同 content + projectId 非空 + 未安排），则**复用该 todo**（设 planDate、保留 projectId、写 `parentTaskRef` 指向项目任务）而非新建。避免未来"项目任务选入计划"出现重复 todo。**关键：复用按 id 链接，非文字**（防②）。

## 4. 数据模型变更（migration 0005）

**文件**：`workbuddy/src/main/db/migrations/0005_task_provenance.ts`，`migrate.ts` 注册（version=5）。

```sql
-- 新建 tasks 表
CREATE TABLE IF NOT EXISTS tasks (
  tid          TEXT PRIMARY KEY,
  planId       TEXT NOT NULL REFERENCES plans(id),
  content      TEXT NOT NULL,
  parentTaskId TEXT REFERENCES tasks(tid),
  consumed     INTEGER NOT NULL DEFAULT 0,
  sortOrder    INTEGER NOT NULL DEFAULT 0,
  isDeleted    INTEGER NOT NULL DEFAULT 0,
  deletedAt    TEXT,
  createdAt    TEXT NOT NULL DEFAULT '',
  updatedAt    TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_tasks_plan     ON tasks(planId) WHERE isDeleted=0;
CREATE INDEX IF NOT EXISTS idx_tasks_parent   ON tasks(parentTaskId) WHERE parentTaskId IS NOT NULL AND isDeleted=0;

-- todos 加 parentTaskRef（JSON 字符串，可空）
ALTER TABLE todos ADD COLUMN parentTaskRef TEXT;
```

- **幂等**：`CREATE TABLE IF NOT EXISTS` + `addColumnIfMissing`（同 0003/0004 范式）；事务包裹。
- **存量**：27 todo `parentTaskRef=NULL`（不回填，降级显示）；`tasks` 表空起（首次保存各 plan 时按 §3.3 填充）。
- **偏差记录**：migration 0005 触「无 migration」规格边界（同 0004 先例），DeepSeek 记 `当前状态.md` 偏差。
