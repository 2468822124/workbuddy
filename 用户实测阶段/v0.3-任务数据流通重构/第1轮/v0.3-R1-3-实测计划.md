## 七、取消、错误降级、恢复和数据一致性要求

### 取消/确认

- **取消路径**：T03-C02 先打开转周确认，再取消；预期确认条消失、H1 保持 W-1 未完成、W0 不新增承接，需保留取消前后截图和只读/页面 checkpoint。

- **二次确认文案**：以实际可见文字为准，但必须能说明转周影响；空提示、无意义红条、确认后无可见状态或入口继续可用均按失败记录。
- T01/T02 没有删除、覆盖、导入、封账或转周动作，取消/确认不适用；不得为了填表增加范围外破坏性操作。

### 错误降级

- **失败场景**：S1 hash 不符、bat Data 路径不符、入口启动失败、保存 BOOT1 失败、I2 场次完成无反馈、复盘统计冲突、转周确认失败、确认后入口未收敛、刷新后状态回退。
- **可读反馈**：页面或入口应显示可理解的状态/错误；未确认的逐字文案写“以实际可见文字为准”，不把技术堆栈或空反馈视为成功。
- **不中断标准**：错误不崩溃、不白屏、不无限重试；在安全状态下可取消确认条、离开页面或正常关闭。
- **数据保护**：入口错误不能写旧/真实目录；T02 错误不能清空或重复凭据；T03 取消不能转周，确认失败不能生成不可解释的半成品承接；不通过清库掩盖问题。

- **需要验证的数据变化**：BOOT1 设置、I2 的三次完成和复盘派生、H1 的取消/确认转周、原项 UI 状态、CARRY1 承接和 `carriedFrom` 关系。

### 安全与隔离

- **不可触碰的真实数据**：`%APPDATA%\workbuddy\` 及其数据库；若进程参数或数据库路径指向该目录，立即阻断并停止。
