### 🔍 GLM 诊断（2026-08-06）

#### 第一次诊断（初始诊断）
**可能根因（按概率排序）**：

**① 单实例锁静默退出（最可能，概率 ~60%）**
- 阶段 6 加了 `app.requestSingleInstanceLock()`：若后台已有一个 WorkBuddy 进程（之前 A1 免安装版 `win-unpacked\WorkBuddy.exe` 启动后未完全退出，或卡死），新实例拿不到锁 → 走 `if (!gotLock) { app.quit() }` 分支 → **静默退出，无窗口、无错误**。
- **这与「无任何反应、无错误」的症状完全吻合**（普通崩溃通常会有「已停止工作」对话框或事件日志）。
- 代码位置：`src/main/index.ts:11-13`。

**② better-sqlite3 native 在安装上下文加载失败（概率 ~20%）**
- 安装版与免安装版的资源路径不同，若 .node 解包在安装目录解析异常 → 启动即崩。但通常会触发 Windows 崩溃对话框或事件日志，与「完全无反应」略不符。

**③ 安装路径含空格导致资源/DB 路径解析失败（概率 ~10%）**
- `E:\workspace test\WorkBuddy` 含空格。Electron 一般能处理，但若某处路径未加引号 / `__dirname` 拼接异常，可能加载失败。可能性较低但需排除。

**④ 缺 VC++ 运行时 / better-sqlite3 依赖的系统库缺失（概率 ~10%）**

#### 第二次诊断（用户三项自检后）

**已排除（据新证据）**：
- ❌ **单实例锁静默退出**：进程能持续运行（"electron (3)"）= 它**拿到了锁**；被拒会 `app.quit()` 不留进程。排除。
- ❌ **better-sqlite3 native 崩溃**：事件查看器**无应用错误、无故障模块**（仅 RestartManager 信息）。native 崩溃必有 .exe 错误事件。排除。
- ❌ **安装路径含空格**：A1 免安装版（无空格路径）**同样失败**。排除。

**锁定方向：阶段 6「生产加固」回归（`app.isPackaged` 才执行的代码路径）**
- 阶段 1–5 全程 dev 模式（`loadURL` 开发服务器），**打包路径（`loadFile` + CSP + 单实例 + Menu 块）从未被实跑**——这是漏网之鱼。
- 症状「进程启动+持续，但窗口永不出现」= `BrowserWindow({show:false})` 的 `ready-to-show` 事件**从未触发** → 窗口永不 show。

**可能根因（重排，按概率）**：

**① loadFile 路径在打包 asar 内解析失败 → did-fail-load → 无 ready-to-show（~50%）**
- `window.ts:33`：`mainWindow.loadFile(join(__dirname, '../renderer/index.html'))`。
- electron-vite 打包 main 后，`__dirname` 在 asar 内的解析可能与 dev 不同；若路径错 → 渲染进程加载失败 → `did-fail-load` → `ready-to-show` 不触发 → 窗口（show:false）永不显示。

**② CSP `script-src 'self'` 阻断 file:// 渲染进程脚本（~35%）**
- 阶段 6 加的 CSP（`src/main/index.ts:33-43`）：`script-src 'self'`。
- 打包后渲染从 `file://.../index.html` 加载；**file:// 协议的 origin 是 opaque/null，CSP 的 `'self'` 不匹配 file://** → 内联/模块脚本被拦 → Vue 不挂载。

**③ 单实例锁 + 首个隐藏实例（~10%）**
- 若首次启动的实例因 ①/② 窗口没显示但进程持锁，后续每次点击都被拒/聚焦到隐藏窗 → 用户永远只看到僵尸进程。

#### 第三次诊断（cmd stderr 抓到，确认根因）

**✅ 确认根因（2026-08-06，cmd stderr 抓到）**

**用户从 cmd 跑 `npm run dev`，输出：**
```
[INFO] WorkBuddy starting...
[INFO] Opening DB: ...\workbuddy.db
[INFO] DB connected, WAL mode
(node:6972) UnhandledPromiseRejectionWarning: Error: Cannot find module './defaultSettings'
    at Object.seedDefaults (E:\workspace\workbuddy\out\main\index.js:288:36)
    at E:\workspace\workbuddy\out\main\index.js:1272:18
```

**根因（非打包加固，是阶段 1 潜伏 bug）：**
- `src/main/db/repositories/settingsRepo.ts` 的 `seedDefaults()` 用了**动态 `require('./defaultSettings')`**。
- electron-vite 打包 main（SSR bundle）时，动态 `require()` 相对路径**不被解析**：模块内容已内联进 `index.js`，但 `require('./defaultSettings')` 调用仍在运行时找独立文件 `out/main/defaultSettings.js`（不存在）→ 抛 `Cannot find module`。
- `seedDefaults()` 在 `app.whenReady` 内、`createWindow()` **之前**抛错 → `createWindow()` 永不执行 → **窗口从未创建**。

## 经验总结

### 问题类型
- **类型**：安装/启动 + 运行时缺陷
- **根本原因**：动态 require 在 electron-vite 打包后解析失败

### 预防措施
- **禁止使用动态 require**：所有模块引用必须使用静态 import
- **打包链路必须实跑**：isPackaged/打包专属代码路径不能只做代码核查
- **错误处理完善**：启动序列应包 try/catch，避免静默失败

### 修复耗时
- **从发现到闭环**：2天（2026-08-06 至 2026-08-07）
