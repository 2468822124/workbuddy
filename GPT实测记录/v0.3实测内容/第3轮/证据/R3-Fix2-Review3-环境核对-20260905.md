## 发现与范围核对

### U5-01：停用边界和确认布局未通过

1. R2 §17.16.5-§17.16.6 的用户批准范围是停用后 W+1 及以后不生成新 F1、W0 存量保留；没有授权删除或改写停用前已经存在的未来实例。
2. `candidate-static-review.json` 从候选 `out/main/index.js` 提取的 `deleteFixedDef` 显示：事务先软删定义，再枚举生效周之后的 active 实例，对没有日行的实例调用 `flowWeekRepo.softDelete(instance.id)`。这会把停用前已存在但尚未进入日任务的未来实例隐藏，超出当前 16 决策的保留/展示边界；不能用“软删除”或删除后的不可见状态代替数据保留正确性。
3. 同一证据提取的候选样式显示 `.def-row { display:flex }`、`.def-title { flex:1; min-width:0 }`、`.def-actions { flex-shrink:0 }`、`.confirm-hint` 没有可用的换行/布局约束。GUI 截图复现了默认窗口下提示与标题、操作区重叠，最大化后仍有挤压。

**结论**：`U5-01` 为 `❌未解决`、`🔴阻断`。这是候选实现和用户批准边界冲突，并伴随核心停用控件布局不可可靠操作；不是用户验收通过，也不是单纯的空环境阻断。
